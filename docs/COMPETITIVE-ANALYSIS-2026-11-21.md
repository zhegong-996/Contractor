# Contractor 对标分析：LobeHub · PaperClip · Super · AutoLoop

2026 年 11 月 21 日。以当前代码与现有测试台为基准，对照四个 Harness 类产品的公开资料与随仓库内置的上游源码，梳理 Contractor 后端与前端的差距、阻断性问题与建议优先级。本文只做分析，不包含代码改动。

参考资料：LobeHub 官方 changelog（v2.x 任务与设备部分）、LobeHub Super-Agent 实践复盘文章、PaperClip 官方产品页与仓库文档、`upstream/superagent` 的 domain/panel 文档、`upstream/autoloop` README、`docs/FRONTEND-BACKEND-AUDIT-2026-11-21.md` 与 `docs/PRODUCT-CAPABILITY-MAP.md`。

## 一、结论

1. **Contractor 的任务执行链已经比 AutoLoop 完整一个层级。** AutoLoop 是零依赖单机内核，只有「事件 → 租约 → 卡片拍板 → 回执」；Contractor 在它之上补齐了工单版本、权限账本、积分池、跨渠道回传、按版本验收和知识沉淀，且已自研调度器替代 AutoLoop。方向正确，不必回头。
2. **真正的差距不在执行链，而在三处：执行前的可判断性、执行中的可视化、执行后的自迭代。** LobeHub 与 PaperClip 的强项恰好是 Contractor 目前的空白：任务进度与运行状态的可视化、触发与唤醒策略的产品化配置、反馈驱动的自迭代闭环。
3. **有一个接近阻断的入口问题。** Contractor 运行时时，项目设备页的「连接设备」按钮不渲染（`agent-operations.tsx` 对 `executionRuntime !== 'contractor'` 才显示），新 Worker 登记入口被藏掉，与「Worker 可插拔」的产品目标冲突。
4. **审计已确认 5 个 P1 阻断项仍然有效**：发单前看不出可执行性、新项目交付接入断链、验收责任人无法移交、设置页故障丢草稿、测试台数据在临时目录。这些是对比分析里最该先修的部分。

## 二、各家业务流程串接

| 环节 | LobeHub | PaperClip | Super | AutoLoop | Contractor |
| --- | --- | --- | --- | --- | --- |
| 事件来源 | 对话、定时任务、Agent 自触发 | 心跳、日程、委派、Webhook/API | Source 事件 | IM 消息、定时 | 工作台、飞书、GitHub、其他 IM |
| 过滤与触发 | Fast Path 规则 + Slow Path 语义判断，唤醒策略可配（关键词、灵敏度、沉默） | Heartbeat 唤醒，按目标/授权判断是否干活 | Trigger 策略 | 插件过滤器 | 持久入站、去重、casual 正则 + 整理模型；触发策略基本不可配 |
| 任务模型 | 对话内建 Task，独立 Task Manager 执行，含子任务依赖 | 任务挂公司目标，原子 checkout 执行锁 | Mandate → Ticket → Assignment | 事件 → 租约 | 项目/主题/工单/版本/子单，租约 |
| 执行 | 设备资源池选设备，本地助理 + 桌面 MCP 连接器 | 跨供应商运行时，沙箱 + MCP | Execution 面板 | 单机命令行 Agent | 本机或远程 Worker，Codex/Claude Code 隔离适配 |
| 人工介入 | 审查面板（双栏 diff、验收报告区分系统错误与未过检查） | 审批门、Governance 阶段 | 三问面板（看什么/健康吗/一件工作的历史） | 卡片找人拍板 | 待办、必答、研发接单、资料授权 |
| 验收与改进 | 反馈点赞/点踩 → 每晚自我迭代 → 回测 | 从 diff/截图/测试验收，技能版本与试跑沉淀 | Policy/Eval 检查 | 无 | 按版本验收 → 知识候选 → 人采用 → 后续工单引用 |
| 计量 | workspace 积分额度、自动充值、套餐 | 公司/Agent/项目/供应商多级预算、告警与硬停 | 无独立账本 | 无 | Token/积分双轨、模型倍率、多池上限、硬停 |

主链差异一句话：**Contractor 把「验收与知识沉淀」做成强制环节，LobeHub 把「反馈自迭代」做成强制环节，PaperClip 把「目标对齐与技能训练」做成核心，Super 把「Eval 策略」做成核心，AutoLoop 只做「派活与拍板」的最短回路。**

## 三、Contractor 已经超出之处

对照四家，以下能力 Contractor 是独有或更完整的，属于护城河，后续改动不要破坏：

- 按版本验收链：工单版本与提交、PR、同 SHA CI、部署证据逐一对应，旧版 CI 不能验收新版。
- 积分账本：Token 用量与积分双轨、模型倍率、平台/整理/个人/项目/Agent 多池、重放不重扣。
- 知识版本与来源授权：候选 → 人工采用 → 替代与历史留存，撤权级联影响原资料与派生知识。
- 跨渠道：身份绑定、原会话回传、回执补写、断线补读，钉钉/飞书/企微登录与消息并存。
- RBAC 数据权限 + 菜单权限 + 项目角色分层（平台管理员/维护人/协作者/读者）。
- 资料临时授权（按工单、Agent、修订、有效期）。
- 已自研 Contractor 调度器，AutoLoop 仅保留兼容迁移路径，核心不依赖第三方运行时。

## 四、差距与问题清单

### A. 机制性缺口（后端）

| 编号 | 缺口 | 对标来源 | 现状证据 | 影响 |
| --- | --- | --- | --- | --- |
| A1 | **无目标（Goal）模型。** 项目/主题/工单不能挂公司目标，执行上下文不继承目标。 | PaperClip Goal Alignment | 代码中「目标」仅指交付仓库，无 OKR/objective 结构 | 长链路任务容易跑偏，验收只对结果不对目的 |
| A2 | **无 Agent 自触发与自迭代。** 定时任务不能迭代工单本身，Agent 不能主动给自己排后续任务或定时汇报。 | LobeHub 定时任务、Super Trigger | `execution/cron.ts` 只有群整理排程，工单均为外部触发 | 观察类、跟进类工作全靠人反复派 |
| A3 | **触发策略不可配置。** 无唤醒关键词、职责灵敏度、被唤醒后沉默、唤醒记录与回放。casual 过滤是硬编码正则。 | LobeHub 策略工程（复盘文核心）、Super Trigger | `discussion.ts` 内一条正则，无配置入口 | 群里多发言时要么全收要么全忽略，只能靠人收拾 |
| A4 | **无反馈自迭代闭环。** 没有点赞/点踩 → 汇总 → 调整 → 回测的回路。回归评估是人工对照，不产出对 Agent 的改进动作。 | LobeHub 反馈机制、PaperClip Evals、Super Eval | 无任何反馈闭环实现 | 同一个坑会反复踩，改进靠人肉 |
| A5 | **预算只有硬停。** 无阈值告警、无自动充值、无套餐包。 | PaperClip 预算告警、LobeHub 自动充值与 packages | 额度达到上限直接暂停新执行 | 凌晨跑空额度后整夜静默，第二天才发现 |
| A6 | **人审点是写死的动作，不是可配置审批流。** 没有审批阶段、多人顺序审批、审批历史聚合。 | PaperClip Governance | 待办动作散在 `human-decisions` 等模块 | 复杂审批（多人签字）表达不出来 |
| A7 | **单租户。** 无多组织；跨租户账号只能拒绝。 | PaperClip Multi-Org | `is_cross_tenant` 仅用于拒绝 | 开源分发后每个部署只能服务一个团队 |
| A8 | **无模板导入导出。** 项目、职责、技能包、额度策略不能打包迁移（含凭据清理）。 | PaperClip company portability | 无导出实现 | 新部署重复配置，社区无法共享整套配置 |
| A9 | **无 Skill Studio。** 技能只能挂载/卸载版本，不能在工作台编辑、试跑、看质量指标。 | PaperClip Skill Studio | `octop-resources` 只有共享与挂载 | 技能沉淀靠外部工具 |
| A10 | **无通用 Routines。** 只有群整理 digest，无 cron/webhook/API 通用例行任务入口。 | PaperClip Routines | `execution/cron.ts` 仅 digest | 定期巡检、报告类工作无法挂进系统 |

### B. 前端与体验缺口

| 编号 | 缺口 | 对标来源 | 现状证据 | 影响 |
| --- | --- | --- | --- | --- |
| B1 | **看板卡片信息太薄。** 无执行进度条、检查点/轮次计数、当前模型/设备徽标；运行中的工单和等待的工单看起来一样。 | LobeHub 任务卡（进度条、T-编号、状态）、PaperClip 任务视图 | `work-board.tsx` 卡片只有状态、标题、负责人、日期 | 项目里几十张单时无法一眼看出哪张在跑、卡在哪 |
| B2 | **无首页仪表盘。** 没有「需要处理 / 运行中 / 每日简报」聚合视图，打开先看到全量看板。 | LobeHub v2 首页 | 无 home 组件，`main.tsx` 直接进项目/看板 | 每天进系统第一眼信息过载 |
| B3 | **代码单没有 diff 审查面板。** 验收看截图录像，但改动内容没有双栏 diff + 文件树。 | LobeHub 审查面板 | 无 diff 组件 | 研发和验收人还得去 GitHub 看 diff |
| B4 | **Worker 接入与状态交互弱，且有入口被藏。** Contractor 运行时项目设备页不显示「连接设备」；在线/离线/暂停与引擎、凭据、范围未区分显示。 | LobeHub 设备工具卡片与引导向导、本地 CLI 检测 | `agent-operations.tsx:37` 条件渲染；审计时 9 台登记 5 台启用 0 在线 | 新设备登记找不到入口，旧设备状态误判——**接近阻断** |
| B5 | **会话与工单回链不完整。** 任务完成后没有明确「交回创建它的对话」，个人会话 / 项目会话 / 工单活动三处来回跳。 | LobeHub 任务交回对话、任务标识 | 会话目录有跳转，无完成回链提示 | 用户找不到「我当时是从哪问的」 |
| B6 | **Agent 三概念混淆。** 「个人 Agent」「成员执行 Agent」「我的 Worker」三者关系没有一处讲清。 | LobeHub 角色清晰：个人助理 = 你，Worker = 设备 | 审计第 7 节点名 | 首次配置即劝退 |
| B7 | **无依赖可视化。** 子任务依赖存在但看不到任务树/时间线。 | PaperClip Org/Task 视图、LobeHub 子任务 | 工单只显示「子工单」文本 | 多 Agent 子任务的主从关系靠记 |
| B8 | **移动端只抽验 4 页。** 任务管理核心路径未完整过 390px。 | PaperClip Mobile Ready | 审计证据节 | 手机上处理待办没有保障 |

### C. 已复现的阻断问题（沿用内部审计）

| 优先级 | 问题 | 证据 |
| --- | --- | --- |
| P1 | 发单前看不出任务能否执行：额度 0、设备全离线仍能提交，卡住后四处找原因 | 真实工单在领取前被额度拦截 |
| P1 | 新项目缺交付接入步骤：交付仓与可信配置依赖部署者，表单整体隐藏代码交付区 | 隔离浏览器实测 |
| P1 | 待验收单缺责任人移交：原发起人失去权限后维护人验收返回 403 | 隔离实例复现 |
| P1 | 设置页后台故障会退出并丢草稿，正常切页签也丢未提交内容 | 两条路径复现 |
| P1 部署 | 测试台运行数据在系统临时目录，账本、回执、在途任务无持久保障 | 临时 Git 工作区曾失效 |
| P2 | 旧额度表单覆盖新值、本地提交到 PR 交接不清、附件失败无就地重试、服务状态文案仍写 AutoLoop、全局设置返回丢上下文 | 审计问题表 |

## 五、建议修复顺序

1. **先补可执行性与入口（第 1 批）**：C 组五个 P1 + B4 Worker 配对入口。做完后，一张单从发起到验收中间不再需要人工拼齐条件。
2. **再补任务管理体验（第 2 批）**：B1 看板进度与运行中聚合、B3 diff 审查面板、B5 回链、B7 依赖视图。直接对齐 LobeHub 任务卡和 PaperClip 任务视图。
3. **再补自迭代机制（第 3 批）**：A3 触发策略配置、A4 反馈闭环、A2 自触发任务、A5 预算告警。让系统在无人盯着时持续改进。
4. **最后做开源分发配套（第 4 批）**：A7 多租户、A8 模板导入导出、A1 目标模型、A10 通用 Routines、A9 Skill Studio。这些决定项目分发给其他团队后的可用性。

## 六、验证边界

本文的 Contractor 现状来自代码审阅与 2026-11-21 审计（基准 ba888df 的后续版本），LobeHub/PaperClip 能力来自公开 changelog、产品页与复盘文章，Super 与 AutoLoop 来自仓库内置上游源码。各外部产品仍在快速迭代，文中对照以写作当日为准。未在真实环境验证的项（B8 移动端、A7 多租户）已按缺口标注，不视为已复现缺陷。
