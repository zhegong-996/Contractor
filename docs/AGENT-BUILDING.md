# Agent 构建与执行

服务 Agent 是成员向同事提供的专业能力。负责人、资料身份、职责、工作方法和执行工具分别配置。组织和知识空间仍由公司配置；不存在固定的产研、增长、销售权限分区。

## 原版代码的实际用途

| 来源 | 正在执行的代码 | SuitMe 接入 |
|---|---|---|
| DeepSeek Harness | Cordis Context 与原生 scope、persona、system-prompt | 每个服务装配独立身份、职责和工作方法；结束时销毁作用域 |
| DeepSeek Harness | ToolsService、native executor、工具管线 | 选定能力限制真实工具目录；服务端再次核对权限、参数和当前职责版本 |
| DeepSeek Harness | preset definition 的 entryListProblem | 校验接入层生成的装配声明；未启动完整 preset registry/AgentLoop |
| Super-agent | settingsPolicy、assessmentOutcome | 判断本轮是否处于已明确的准备范围；不是审批替身 |
| Autoloop | 原版 worker、CLI adapter、回执与恢复 | 每次只消费一个 Paperclip 原生 run；等待人时结束本轮 |
| Paperclip | 原生成员、独立 Agent、任务、签出、权限、文档与修订 | 唯一任务和运行真源；真实账号认证，不靠前端传来的职位标签 |
| Cognee / Prime Agent | 持久来源版本图、BM25、知识字典、检索词 | 在原生 ACL 与本次任务许可之内检索；概念与关系仍由人采用 |

固定版本和许可证见 [SOURCES](SOURCES.md) 与 [第三方声明](../THIRD_PARTY_NOTICES.md)。上游没有修改。`esbuild` 将选定模块打包到运行目录；不是自行重写一套 Harness。

## 前端构建

“Agent → 登记 Agent”包含名称、个人/公共类型、职责、能力、工作方法、执行约定、上下文范围与每轮工具预算。工作方法依赖对应能力，不能悄悄开启工具。构建检查真实装配原版作用域并返回实际工具清单，不发模型请求、不创建资料授权。

知识、访问申请、协作、知识关系候选、交付证据与有界复查是可选能力。个人 Agent 只能使用本人的资料身份；其他人的私有执行约定不出现在服务目录。服务负责人不能通过修改 ownerUserId 接管其他 Agent。正在执行的任务绑定职责版本，变更后先核对再继续。

负责人可选择本人负责的资料，向同事展示可申请的名称。这不是共享正文；资料必须先纳入具体任务、说明用途和期限，再由资料负责人批准。未列出的内部资料不会进入同事的目录。

## 执行与交付

模型通过当前任务绑定的 MCP 工具工作。MCP 只展示构建后允许的工具，服务端原生执行管线仍会拒绝伪造调用；每轮最多 2–12 次。工具取数前后复核身份、确切版本和授权。子任务强制只读取本次明确交接的资料，不扫描负责人整个知识空间。

同事间委托创建不同成员资料身份持有的原生子任务，通过 A2A 接单、等待、澄清和回传。调用别人的服务不会把需求方放到自己看不到的任务里。只有双方仍有访问权，成果正文才回传；撤权后只保留状态。

开发交接使用现有 Autoloop/Codex 代码执行端。需求发起人在前端核对并填写允许交付的实现说明，系统不把私有来源正文直接拷进 GitHub。PR、CI、同 SHA 预览、逐项验收分别记录。最终验收仅原需求发起人可操作；委托开发的父任务必须等关联开发按版本验收。

临时授权不包含永久共享权。基于其他负责人资料产生的成果不能仅凭临时授权发布为永久知识；由资料负责人在其有权负责的空间审阅采用。撤权不会删除所有已被人看过的副本，但会拒绝后续 API、检索、任务输入和服务回传，并收回对应原生派生记录 grant。

## 隔离的三成员演练

运行 `node --import tsx scripts/run-team-pilot.ts --run --setup --install-plugin` 可建立独立的模拟实例：原生认证 3110、接入层 4181、独立数据库和运行目录。三名业务成员均为 operator，另有一个只做环境配置的技术管理员。用户、业务和资料明确标记为模拟；模型执行、任务、授权和测试仓库 PR 使用真实服务。

凭据保存在忽略的 `.runtime/team-pilot/pilot-secrets.json`；不要提交、复制到业务文档或通过 URL 传播。`scripts/verify-team-pilot.ts --run` 只核对已从前端创建的任务、真实身份和资料权限，不代替前端的正向申请、授权与验收操作。新的真实员工、真实资料及生产发布仍需相应部署与授权。
