# SuitMe 产品架构

> 版本口径：第三十六轮（2026-11-09）。产品分层、角色模型、对象模型与产品红线。
> 设计定稿（v0.6 六层模型）见 [ARCHITECTURE-v0.6.md](../ARCHITECTURE-v0.6.md)。

## 1. 产品定位与形态

**一句话**：本机运行的 AI 员工协作台——「人在自己的会话里发起，Agent 在工作台里干活，验收权永远在人」。

产品形态 = **一个会话入口 + 一个工作台 + 一套治理**：

| 形态 | 载体 | 产品角色 |
|---|---|---|
| 会话入口 | 飞书（主）、钉钉/企微（补充）、CLI | 工作从这里开始，通知回到这里 |
| 工作台 | Paperclip 3100（全中文） | 记录、授权、审批、预算、运行活动的家 |
| 治理 | 审计 + 红线 + 注意力预算 | 决定「AI 不能替人做什么」 |

## 2. 产品分层（六层模型）

```
L6  会话层    人与 Agent 的对话面：提问卡片、回答路由、到点复查
L5  组织层    Agent 注册表、业务域路由、成员配对、服务网
L4  协作层    任务、交接授权(Transfer)、验收合同、审批
L3  执行层    步进执行、适配器、挂起零消耗、崩溃接棒
L2  知识层    知识空间、三层记忆、组织图谱、语义检索
L1  交付层    本机 Git 交付台、CI 核对、版本证据、预览
```

每层向下依赖、向上暴露语义对象（Transfer 卡、验收报告、上下文授权、任务通知），**任何语义对象必须同时渲染成「会话文本 + 工作台链接」**——降级不丢语义字段。

## 3. 角色模型

| 角色 | 谁 | 能做什么 | 不能做什么 |
|---|---|---|---|
| 原发起人（owner） | 你 | 发起任务、回答问题、**确认验收/核可/放行** | — |
| 管理者（admin） | 本机操作者 | 全部管理操作、绑定通道、配置例程 | 不替发起人验收 |
| 成员（member） | 配对的真人 | 在授权范围内接单、回答 | 越权访问、验收他人任务 |
| 主管 Agent | 业务域 supervisor | 域内派活、初审、汇总 | 跨域派活、自定验收标准 |
| 个人 Agent | 某成员的 agent | 只服务其 owner 的委托 | 转发未授权资料 |
| 公共服务 Agent | 职责目录中的服务 | 可行性/起草/评审三档服务 | 冒充个人 Agent |
| 自动化 actor | 定时器/GitHub 监听 | 发起任务、触发复查（全程留痕） | **任何验收/核可/放行** |

## 4. 核心对象模型

| 对象 | 关键字段 / 约束 | 生命周期 |
|---|---|---|
| **Task（任务）** | 幂等 requestKey；phase: ready→running→delivered→accepted | 建单→路由→执行→交付→验收 |
| **Transfer（跨职能授权）** | 授权人/承接人/能力依据/范围/验收标准起草方/联签人 | 交接时签发，本 Task 结束即失效 |
| **验收合同** | 开工前锁定逐项计划；评审者不得是产出模型 | 执行中 immutable，判定逐项进行 |
| **HITL 提问/回答** | 成对台账；回答 ≠ 验收 | 提问→挂起→回答→自动续跑闸（重新验证） |
| **Wake（复查预约）** | taskId + at + note；到点触发一轮复查委托 | 预约→scheduled→done/cancelled |
| **Routine（例行任务）** | schedule(interval/daily) + goal；时间槽幂等 | 每槽至多触发一次 |
| **知识空间/条目** | 分区权限（RBAC）；跨空间需授权 | 创建→入库→引用→撤权沿 lineage 阻断 |
| **团队记忆** | 打回原因、验收标准等沉淀；候选改进须真人批准 | 沉淀→审批→生效 |

## 5. 产品红线（不可配置）

1. **验收、核可、放行只在原会话由原发起人确认**——定时器、监听器、通道、Agent 都不能碰。
2. **回答不是验收**——自动续跑闸执行时必须重新验证台账里的回答，不盲信入参。
3. **候选改进必须真人批准**——Agent 不能自己把改进改生效。
4. **不得改写清单/权限/人签/历史任务**。
5. **注意力预算对人类必达消息永远放行**——护栏只能抑制低价值通知。

## 6. 本轮产品边界变化（第三十六轮拍板）

用户 2026-11-09 拍板「这几个也都要做」，**放宽**了此前的两条边界：

| 旧边界 | 新口径 |
|---|---|
| 飞书是唯一发起入口 | 定时调度器、GitHub 监听也可发起任务（automation actor 全程留痕，任务卡片写明「自动发起」） |
| 不监听 GitHub（交付走本机 Git） | 监听 GitHub 事件转任务；**交付链路仍按 delivery 配置走（默认本机 Git）** |

**未变**：企微加密模式回调未支持（明文可用，如实报错）；钉钉/企微出站需先配 webhook 环境变量；webhook 入站端点需公网反代。

## 7. 三个上游平台的能力映射

| 平台 | 借鉴 | SuitMe 落地 |
|---|---|---|
| Agent Autoloop | 循环与状态分离、事件溯源 | 步进泵 + PG 队列 + 挂起零消耗 + 唤醒复查 |
| Super Agent | IM 接单、原会话回答 | 飞书接单 + P-9 双向回路 + 会话回答路由 |
| LobeHub（acceptance） | 验收方法论（设计语言，不复制代码） | 验收合同/判定/报告/打回记忆全链 |

逐项对照与证据见 [FEATURE-PARITY.md](../FEATURE-PARITY.md)。
