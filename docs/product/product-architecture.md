# SuitMe 产品架构

> 版本口径：第四十一轮（2026-11-09）。产品分层、角色模型、对象模型、准入与派活与直通、产品红线。
> 分层契约的逐条验证见 [LAYER-CONTRACTS.md](../LAYER-CONTRACTS.md)；
> 设计定稿（v0.6 六层模型）见 [ARCHITECTURE-v0.6.md](../ARCHITECTURE-v0.6.md)。

## 1. 产品定位与形态

**一句话**：本机运行的 AI 员工协作台——「人在自己的会话里发起，Agent 在工作台里干活，验收权永远在人」。

产品形态 = **一个会话入口 + 一个工作台 + 一套治理**：

| 形态 | 载体 | 产品角色 |
|---|---|---|
| 会话入口 | 飞书（主）、钉钉/企微（补充）、CLI、MCP | 工作从这里开始，通知回到这里 |
| 工作台 | Paperclip 3100（全中文） | 记录、授权、审批、预算、运行活动的家 |
| 治理 | 审计 + 红线 + 注意力预算 + 分层契约体检 | 决定「AI 不能替人做什么」，并能自证 |

## 2. 产品分层（六层模型 + 两条路径）

```
L6  会话层    人与 Agent 的对话面：提问卡片、回答路由、到点复查、直通接续
L5  组织层    Agent 注册表、业务域路由（1~2 跳）、成员配对、服务网
L4  协作层    任务、交接授权(Transfer)、验收合同、审批
L3  执行层    步进执行、适配器、挂起零消耗、崩溃接棒
L2  知识层    知识空间三分区、三层记忆、组织图谱、语义检索
L1  交付层    本机 Git 交付台、CI 核对、版本证据、预览
```

每层向下依赖、向上暴露语义对象（Transfer 卡、验收报告、上下文授权、任务通知），**任何语义对象必须同时渲染成「会话文本 + 工作台链接」**——降级不丢语义字段。

## 3. 进门先定身份：准入三档（第四十一轮）

消息进来第一步不是派活，是回答「这个人算不算我们的人」。三档只认证据，不猜：

| 档位 | 证据 | 处理 | 成员身份 |
|---|---|---|---|
| 显式准入 | 已配对出在职成员；或单负责人安装里白名单唯一登记的人 | 走完整链路 | 前者有，后者无 |
| 推断准入 | 配对记录在但身份失效；或多人白名单里未配对 | 只回一条配对指引 + 留待确认，不建单 | 无 |
| 未准入 | 通道也不认 | 拒绝，只留审计，不回话 | 无 |

「推断准入不自动放行」是刻意的：自动推断身份等于自动授权。

## 3.1 派活的两条路径（第四十轮明确，第四十一轮补交回与释放）

| 路径 | 触发 | 走不走 Router | 会不会新建任务 | 权限变化 |
|---|---|---|---|---|
| **主链路** | 新需求（飞书 / 工作台 / 定时器 / GitHub / 通用事件源） | 走；flat 1 跳，layered ≤2 跳 | 会 | 按发起人 + 通道白名单 |
| **直通** | 同一人在同一会话里对**已绑定任务**补充说明 | 不走 | 不会 | **不变**（结构上不带 scope 字段） |
| **交回** | 补充说明要改授权面（换人 / 改清单 / 加权限 / 换来源） | 交回主链路 | 不接续 | 不因这句话改变 |

直通的四条红线：只认原绑定、不复活已完成 / 已释放任务、显式指令（确认验收 / 退回 / 转交）一律回主链路、
成员归属不符直接拒绝。会话在任务验收时**释放**（写 `subscription.released` 审计），释放是终态。
见 [LAYER-CONTRACTS.md](../LAYER-CONTRACTS.md) §2。

## 4. 角色模型

| 角色 | 谁 | 能做什么 | 不能做什么 |
|---|---|---|---|
| 原发起人（owner） | 你 | 发起任务、回答问题、**确认验收/核可/放行** | — |
| 管理者（admin） | 本机操作者 | 全部管理操作、绑定通道、配置例程、组织区知识增删 | 不替发起人验收 |
| 成员（member） | 配对的真人 | 在授权范围内接单、回答、写协作区知识 | 越权访问、验收他人任务 |
| 主管 Agent | 业务域 supervisor | 域内派活、初审、汇总、组织区知识 | 跨域派活、自定验收标准、替人签字 |
| 执行 Agent | worker | 域内干活、写协作区知识 | 改组织区知识、验收 |
| 个人 Agent | personal | 只服务其 owner 的委托 | 转发未授权资料、写知识 |
| 公共服务 Agent | 职责目录中的服务 | 可行性/起草/评审三档服务 | 冒充个人 Agent |
| 自动化 actor | 定时器 / GitHub 监听 / 事件源 | 发起任务、触发复查（全程留痕） | **任何验收/核可/放行** |

## 5. 核心对象模型

| 对象 | 关键字段 / 约束 | 生命周期 |
|---|---|---|
| **Task（任务）** | 幂等 requestKey；phase: ready→running→delivered→accepted | 建单→路由→执行→交付→验收 |
| **RoutingDecision（派活决策）** | caller / target / basis / scope / outcome；append-only | 每次派活 1~2 条，可重放 |
| **Transfer（跨职能授权）** | 授权人/承接人/能力依据/范围/验收标准起草方/联签人 | 交接时签发，本 Task 结束即失效 |
| **验收合同** | 开工前锁定逐项计划；评审者不得是产出模型 | 执行中 immutable，判定逐项进行 |
| **HITL 提问/回答** | 成对台账；回答 ≠ 验收 | 提问→挂起→回答→自动续跑闸（重新验证） |
| **Wake（复查预约）** | taskId + at + note；到点触发一轮复查委托 | 预约→scheduled→done/cancelled |
| **Routine（例行任务）** | schedule(interval/daily/cron) + goal；时间槽幂等 | 每槽至多一次；cron 30 分钟补跑窗口 |
| **事件收件箱（Inbox）** | 逐来源密钥、指纹幂等、只收事实不开工单 | 收到→pending / mirrored |
| **知识空间/条目** | 三分区（personal / team / org）；跨空间需授权 | 创建→入库→引用→撤权沿 lineage 阻断 |
| **团队记忆** | 打回原因、验收标准等沉淀；候选改进须真人批准 | 沉淀→审批→生效 |

## 6. 产品红线（不可配置）

1. **验收、核可、放行只在原会话由原发起人确认**——定时器、监听器、通道、Agent 都不能碰。
2. **回答不是验收**——自动续跑闸执行时必须重新验证台账里的回答，不盲信入参。
3. **候选改进必须真人批准**——Agent 不能自己把改进改生效。
4. **不得改写清单/权限/人签/历史任务**。
5. **注意力预算对人类必达消息永远放行**——护栏只能抑制低价值通知。
6. **直通只少建单、不多给权**——旁路不得携带新的范围或权限。
7. **同一 Task 禁止自派自验自环**——承接人、产出方、评审者两两不得同一主体。

## 7. 边界变化时间线

| 轮次 | 变化 |
|---|---|
| 第三十六轮 | 定时调度器 / GitHub 监听 / 钉钉企微 / 唤醒复查四件套落地；「飞书唯一入口」「不监听 GitHub」两条旧边界放宽 |
| 第三十七轮 | cron 排班；复盘把「全部实现」修正为「核心闭环全通 + 周边待补」 |
| 第三十八轮 | Acceptance 成为一等模块；独立审码阶段；通用事件源；验收矩阵 |
| 第三十九轮 | 事件源默认开启并单向归属；矩阵扩到 7 视图；并发按密度缺省；通道体检 |
| 第四十轮 | 直通契约化；知识新建与修改口径统一；40 条分层契约体检；三上游对标 |
| 第四十一轮 | 准入三档；订阅交回与释放；报告内讨论 + 区域点选；知识读按域收窄；规则视图；一条命令安装；45 条体检 partial 清零 |

**未变**：企微加密模式回调未支持（明文可用，如实报错）；钉钉/企微出站需先配 webhook 环境变量；
webhook 入站端点需公网反代；跨空间知识读取仍不按业务域收窄（已有边界，见 LAYER-CONTRACTS §5.3）。

## 8. 三个上游平台的能力映射

| 平台 | 借鉴 | SuitMe 落地 |
|---|---|---|
| Agent Autoloop | 循环与状态分离、事件溯源、挂起零消耗、cron | 步进泵 + PG 队列 + 唤醒复查 + 定时调度器 |
| Super Agent | IM 接单、原会话回答、订阅直通不授予新权限 | 飞书接单 + P-9 双向回路 + `pass-through.ts` |
| LobeHub（acceptance） | 验收方法论（设计语言，不复制代码） | 验收合同/判定/报告/打回记忆全链 |
