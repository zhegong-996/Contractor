## 一句话定位

**SuitMe 是一台跑在你自己电脑上的「AI 员工协作台」**：一群 Agent 像同事一样接活、干活、互相交接，遇到需要人拍板的事就来问你，干完的活按证据验收，沉淀的经验回流成组织记忆。数据在本机、模型凭据自己管、验收权永远在人手里。

## 解决什么问题

| 现状痛点 | SuitMe 的做法 |
|---|---|
| 单个 AI 助手只能聊天，干不了跨岗位的活 | 任务在一群职责分明的 Agent 之间路由、交接、互相评审 |
| AI 干活黑盒，不知道它干了什么、花了多少 | 每一步都有事件留痕、审计台账、成本账本，可回放可追责 |
| AI 自作主张替人做决定 | 提问链路 + 审批链 + 验收红线：**核可、放行、验收永远由原发起人确认** |
| 干完就忘，下次从零开始 | 打回记忆、团队记忆、知识库三层沉淀，经验复用 |
| 云端 SaaS 担心数据外泄 | 全本机部署：任务、知识、凭据不出你的电脑（外部模型调用显式配置、显式留痕） |
| 说不清「架构到底有没有落地」 | 40 条分层契约体检，一条命令复跑，gap 直接退出码 1 |

## 核心能力清单（当前全部可用）

### 1. 多 Agent 协作与派活
- **组织编制**：Agent 有职责、生效范围、版本、在岗状态（组织级注册表）；空编制就是扁平，不硬造管理层
- **分层路由**：五个派活点统一经 Router；`flat` 1 跳、`layered` 最多 2 跳；主管必须真实在岗、职责匹配、范围覆盖
- **直通**：同一会话的补充说明直接接续原任务，不建单、不过 Router、**不多给一份权**
- **任务交接**：跨职能转交带授权卡（Transfer），交接只给引用与范围，不搬正文
- **服务网**：个人 Agent 与公共服务（可行性/起草/评审三档）按职责目录调用

### 2. 长程执行（autoloop 模式）
- **挂起零消耗**：等人拍板时进程退出，不烧 token；回答到达自动续跑
- **步数熔断**：单 run 步数上限，防失控循环
- **状态外置**：PostgreSQL 步进队列，进程崩溃可接棒，换机器可继续
- **到点唤醒复查**：任务可预约「X 时间后复查」，到点自动唤醒一轮

### 3. 自动化入口
- **定时调度器**：例程（interval / daily / cron）到点建任务；并发按密度缺省；**跳过不静默**
- **GitHub 监听**：轮询 + webhook 两种方式，事件自动转任务（验收不放行，合并走审批链）
- **通用事件源**：`POST /events/:source`，逐来源密钥、指纹幂等、只收事实
- **钉钉/企微通道**：出站镜像（与飞书共享注意力预算），入站端点可选

### 4. 会话入口
- **飞书**（主通道）：发消息建任务、接续任务、回答问题、确认验收
- **Paperclip 工作台**（3100）：全中文的仪表盘、任务、代理、待办、审批、目标、预算界面
- **管理控制台**（4200）：只读运维 + 语义检索 + 个人配置（7 视图）
- **CLI / MCP**：本机命令行与工具协议接入

### 5. 知识底座
- **知识三分区**：个人区（只有本人可改）/ 协作区（operator 及以上）/ 组织区（admin 及以上），Agent 另按业务域收窄
- **可复用闸**：confirmed + 有确认人 + 同公司 + HMAC 一致 + 未过期，缺一条就排除并写明原因
- **证据锚点**：每条候选知识必须挂回共享记忆主干，悬空证据拒收
- **三层记忆**：会话记忆 → 团队记忆（打回沉淀）→ 知识库（验收后入库）
- **图谱与检索**：L1 零模型投影 / L2 组织图 / Cognee 原生管线 / BM25 + 设备端向量

### 6. 交付与验收
- **本机 Git 交付台**：代码成果进本机裸仓库，按确切提交与本机 CI 结果验收
- **验收合同**：开工前锁定逐项计划，评审者不得是产出模型；清单被替换即作废
- **独立评审 + 独立审码**：视觉证据做结构核对；命中密钥 / `.env` 即拦预览
- **一条链接报告 + 只读工作台**：页面上刻意没有通过 / 打回按钮，验收只能回原会话
- **打回记忆**：只退未过项，原因沉淀进团队记忆，下轮交付前强制比对

### 7. 治理、自证与个性化
- **RBAC**：人与 Agent 共用 casbin 策略；人四级 + Agent 三档；策略文件被改宽会被体检抓出来
- **注意力预算**：低价值通知被抑制，人类必达消息（提问/验收/授权）永远送达
- **三项体检**：服务体检（实时探测）/ 通道体检（零外部请求）/ 分层体检（40 条契约）
- **个性化**：每人的默认视图、主题、刷新间隔、通知开关、模型偏好；个人区知识只有本人可改；个人 Agent 按成员配对
- **凭据纪律**：API key、webhook、DSN 一律走环境变量或 0600 本机文件，绝不入库

## 界面一览

| 入口 | 地址（本机） | 用途 |
|---|---|---|
| Paperclip 工作台 | http://127.0.0.1:3100/ | 主界面：仪表盘、任务、代理、待办、审批、目标 |
| 管理控制台 | http://127.0.0.1:4200/ | 只读运维：概览 / 协作 / 组织 / 知识 / 验收 / 服务 / 我的配置 |
| Bridge API | http://127.0.0.1:4180/ | 所有能力的 HTTP 接口（workspace action 协议） |

## 上游开源复用（7 个 submodule，全部锁定提交）

| 上游 | 复用部分 |
|---|---|
| Paperclip | 工作台前端 + 任务调度核心 + 审批 |
| Super-agent | 飞书消息归一化、幂等回复、策略门控、订阅直通口径 |
| Autoloop | worker、执行适配器、cron、进程与回执恢复 |
| Acceptance（LobeHub 设计语言） | 验收计划/判定/报告/打回记忆的方法论 |
| Cognee | 图谱存储、来源追踪、cognify 管线 |
| DeepSeek Harness | Agent 身份装配、提示词与工具限制 |
| Prime-agent | 会话参考与序列化工具 |

## 开始使用

```sh
git clone --recurse-submodules https://github.com/zhegong-996/suitme-collab.git
cd suitme-collab && npm install && npm run up
# 打开 http://127.0.0.1:3100/
```
