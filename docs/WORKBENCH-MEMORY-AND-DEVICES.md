# 协作记忆、执行端和额度

## 从工作里积累记忆

验收留下成果版本、已确认的问题和原始资料引用。验收后的候选由知识所有者核对正文和适用条件，再决定采用或替代。协作沉淀页显示工单产生的候选、来源和状态。同名且同一所有者的现行条目可在候选旁对照。项目公开的短口径可由项目维护人固定，每项目最多两条。

发起委托时可以勾选「查找相关的现行项目记忆」。个人代办默认勾选。工作台先查已采用的常用口径，再利用现有 BM25 选项目内相关条目，最多自动装配三条，资料总数仍为八条。正文、条件和现行版本在派工时再次核对。受限资料通过已有工单授权流程引用。知识页的「试查项目记忆」与委托共用检索逻辑。

装配快照保留确切资料 ID 和修订。执行端在成果中输出与本轮资料一致的引用标识时，使用记录将该次执行标为「成果已引用」，并链接到确切轮次与尝试。其余装配记录显示为「已装配」。知识详情、工单上下文和 Agent 记忆页均按当前授权再次读取。旧的受限版本撤权后，使用记录和派生知识的访问随之收回。

逐项产品验收生成的候选可在审核后成为主题验收知识。同主题任务按适用范围装配，并保留原工单版次与检查、PR、CI 的出处。需要更新规则时，使用当前依据独立核对，再在候选采用时选择被替代的版本。详见[交付与需求验收](WORKBENCH-DELIVERY-TEMPLATE.md)。

后台维护首版使用已有版本、引用链、候选和权限判定，支持固定、对照同名候选、替代和失效。未来启用跨工单模型归纳时，可以把增量回看作为平台额度下的一项独立工作，并继续交由人采用。

## 登记 Agent 和执行端

Agent 档案记录负责人、职责、可服务的项目、模型和凭据引用。维护实例配置的人把档案写入 `COLLAB_STATE_DIR/workbench.json` 的 `agents`，在实例目录按成员配置凭据，并把可上岗的档案设为 `active: true`。修改配置后重启工作台。档案所有者可以在页面暂停或恢复接单。新安装的样例配置不预置 Agent，字段和项目关系见 [配置 Contractor](CONFIGURATION.md) · [成员凭据配置](MEMBER-EXECUTION-ISOLATION.md)

| 用途 | 配置与入口 |
| --- | --- |
| 平台整理 | 单独配置一个在岗专项 Agent，项目的 `discussion.agent` 指向它。用 `discussion.model`、`effort` 和 `cron` 设置整理使用的模型、推理强度和时间。项目的 `dispatch` 决定按职责派工，候选不唯一时请负责人决定。 |
| 个人 Agent | 档案设为 `kind: personal`，`owner` 为成员账号，`projects` 为可用项目。本人在档案选择「交给我的 Agent」发起只读代办。成员也可按项目职责委托同一个 Agent，记入项目执行额度。 |
| 任务执行端 | 已在岗的 Codex Agent 可登记独立的接单进程。同一个档案可绑定多个执行端。每条绑定核对项目、Agent 和所有者。 |

### 配对本机执行端

1. 在「Agent → 执行端 → 连接本机」用已配置、在岗的本人 Codex Agent 生成一次性码。绑定范围是当前项目和该 Agent，验证码有效期为十分钟。
2. 在工作台所在设备使用相同的 `COLLAB_STATE_DIR`，运行 `npm run runner -- pair 4280 "研发本机"`。按提示从标准输入提交配对码。
3. 运行返回的 `npm run runner -- connect <执行端 ID>`。项目页面会显示在线、离线或暂停接单。
4. 发起工单时先选 Agent，再选为它登记的执行端。已登记端离线时，该工单等待它上线。也可在原工单选择「接续执行」并指定同一 Agent 的另一执行端。

首版同主机接单进程直接调用固定版 AutoLoop worker。服务端复用其领取、心跳、启动、停止和回执语义，并按项目、Agent 和本轮设备筛选原生队列。连接凭据保存在当前运行目录，配对还需证明可读同一主机私有文件。每台登记的执行端有独立的 worker 目录。工单、授权、代码准备和沙箱仍由工作台统一核对。切换前继续使用原有停止证据，并将确认人答复、资料版本和获准的代码改动带入新一轮。

同主机的隔离 Codex 使用现有的配对方式。远程执行端使用单独的入口。执行端的配对凭据与 Agent 的模型凭据分别存放。[远程执行端](WORKBENCH-REMOTE-RUNNER.md)

后续接第三方服务可以沿用 AutoLoop 领取、回执和取消的接口，将厂商任务 ID 挂到本轮租约。CLI 适配器负责启动、解析结果以及确认进程退出。HTTP/A2A 适配器负责把领取映射为服务任务，查询终态、追回执以及确认取消。端点、凭据和资料权限从受信配置提供，按本轮授权装配。收到取消请求后需要核对任务终态再办理交接。[AutoLoop 协议](https://github.com/KKKKhazix/agent-autoloop/blob/ba8cf6d8cf24f9ce005958c15d88f2d9cff7f05d/docs/protocol.md) · [A2A 任务协议](https://a2a-protocol.org/latest/specification/agent-card/)

## 三类额度

| 额度 | 计入 | 调整者 |
| --- | --- | --- |
| 平台调度与定时整理 | 派出的群反馈整理模型轮次 | 实例所有者 |
| 个人 Agent | 本人在 Agent 档案发起的只读个人代办 | 实例所有者 |
| 项目任务执行 | 项目协作派给工作台或已登记执行端的轮次 | 项目维护人 |

每次派出按原生运行 ID 和尝试号记一次。人答复前等待、设备离线等待、无消息的整理窗口均不派出模型执行。每日或每月周期按上海时间。限额为 0 可暂停下一次派出，同时可缩短原有单轮时限。派出后的取消和重试保留实际尝试及可观测的回执。金额缺失时显示为未报价。旧版项目金额门槛保留。

## 验证

门店推荐理由隔离实例使用真实 Codex 和两个独立配对的同主机接单进程。个人 Agent 先提交结论，由设计测试身份按成果版本验收并采用。第二张工单自动检索该记忆，指定的 A 离线时保持等待，切换到 B 后接续原工单并在成果里引用该精确修订。项目执行扣一次，个人代办扣一次，个人额度耗尽后下一张代办阻断。外部项目测试身份不能读取该项目的记忆使用记录。本轮的外部模型账号沿用已有授权试点，工单和资料为虚构门店内容。

回归另覆盖口径替代后自动检索新版、历史依据，以及受限资料撤权后使用记录和派生知识不可访问。浏览器验证了记忆页、版本回链、固定口径、额度调整、在线状态和手机入口。

随后用三个测试成员和三个独立 Agent 档案复查执行。通过本地飞书事件夹具注入虚构反馈，实际工作台按 cron 唤起平台 Agent。平台的 `low` 覆盖该档案的 `high` 默认值，低额度的空窗口正常结束，有新候选时才创建额度待办。个人 Agent 从本人账户提交只读工单，研发 Agent 从实际配对的本机进程领取项目工单。三类回执各结算一次，CLI 会话均报告实际模型 `gpt-6.1-sol`。同一轮也验证了冒用个人 Agent、选错执行端、跨项目查询、缺少同主机证明，以及给 Claude Code 或 Cursor 档案配对均遭拒绝。
