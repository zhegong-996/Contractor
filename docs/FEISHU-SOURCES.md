# 飞书来源与可配置协作

空间是项目、主题或团队的资料组织方式，不是预设部门边界。现存的产研、增长、销售、职能只作为早期实例保留；业务运行、知识标签和参与者校验均不使用这四项枚举。空间名称、责任身份和可选执行身份可在后台配置。参与者可拥有多个空间的原生成员关系，并在其他任务中获得限时资料访问。

## 两层访问约束

1. 原来源访问：官方 lark-cli 使用已登录用户身份，固定 profile、应用和用户 open ID。每个操作重新读取来源，使用 CLI 自带的认证与续期，不导出 token。
2. 任务委托：原始飞书引用存于原生私有 vault，不因空间分类而授予成员读取。需对具体来源、任务、执行身份、用途及期限进行明确批准。任务换人会回收旧身份的任务授权；其他任务的独立有效授权保持各自范围。

当前是本机管理员的定向代理模式，不是四类员工账号，也不把管理员的可见范围自动继承给所有 Agent。多人部署仍需将每位用户/服务身份的来源连接及组织成员映射接入；不能凭部门名称推测飞书 ACL。

## 原文与知识分开

- 支持 Docx 当前正文与明确选中的历史消息 ID。后台可新增 Docx 引用；其他文档类型暂不冒充已接通。
- 来源对象只存定位与连接绑定。正文在获准的任务中实时取得，保存版本与内容指纹，沿用上下文裁剪、覆盖标记和逐字引用校验。生成依据已经变化的历史工作稿保留审计，但不再进入新模型输入。
- 原始消息及文档保持“来源证据”身份，不自动确认成专业知识。历史讨论有原时间及链接，不代表当前决定，更不能作为授权依据。
- 选定消息撤回、遗漏、含凭据或不可读取时，整个已批准讨论范围停止使用，需重新确认；不从旧缓存回填。只在同一后台操作内合并重复读取，不使用跨操作正文缓存。
- 连接身份变化或来源永久不可访问时，后台回收相应任务授权及派生文档 grant。临时网络错误同样停止本轮读取，不自动扩大身份或改用管理员缓存。
- 知识候选、采用和最终验收继续分开。人可以按精确工作稿版本记录“本次暂不采用知识”的验收依据；无需为了结束任务强制发布知识。飞书原文、私有工作稿和运行输入仅留本机及原生私有审计记录，不提交代码仓库。

## IM 接续

沿用 Super-agent 原始事件归一化及既有白名单、事件去重和原处回复。管理员先将任务绑定到唯一获准发起人和会话，随后使用 `/collab <任务号> 接续`。它接续同一个任务，不新建副本，不从消息中接受身份、资料或权限参数；`暂停`停止自动整理，其他文字作为本任务背景补充。

协作父任务由原生人工审阅路径维护；实际模型工作由既有原生子任务/run 执行。开发执行器遇到协作任务会在领取前退出，避免误把私有资料整理当成代码开发并发布。只有具名人类评论进入讨论证据，匿名系统修复提示及机器回复不会触发归纳循环。

## 本轮验证范围

自动检查覆盖身份漂移、原文修订、操作级缓存、来源失效、消息排除、任务委托、非预设空间、IM 去重和原生人工审阅入口。真实项目使用当前授权的 Roadmap 与选定群讨论，真实 Codex 产出待审阅稿；详细输入、原链接及运行回执留在忽略提交的 .runtime 内。真实知识采用和业务验收须等待用户审阅，不以自动测试或模型完成替代。
