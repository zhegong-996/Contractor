# 产品功能齐全度盘点

> 用户要求：全面盘点功能是否齐全，对比同类项目（dsh-superagent / lobehub acceptance /
> agent-autoloop / LobeHub 主项目），找出差异与没做好的地方。本文按「层」给全景，如实标注
> 成熟度与缺口，不粉饰。

## 0. 一句话结论

**判定层（谁有资格、什么算验收、越界怎么退）是这个系统最强的部分，做得比三个上游都细；
协作层（Agent 委托）刚补、刚接飞书 `/do`，还没完全融进执行链；
前端是单页控制台，和 LobeHub（84k star 完整产品）差一个数量级。**

## 1. 功能全景（120+ 模块，按层）

| 层 | 已有什么 | 成熟度 | 缺什么 |
|---|---|---|---|

## 2. 对比三个上游项目

| 维度 | dsh-superagent | lobehub acceptance | agent-autoloop | **我们** |
|---|---|---|---|---|
| 准入/授权 | 三档 + Mandate | — | 字段白名单 | ✅ 三档 + 订阅 + 越界 + 指令分离（更严） |
| Agent 委托 | Router+Worker | coordinator/runner/checker | rules 派活 | ✅ 委托链(刚补) + 会签 + 跨域委派 |
| 验收 | PR review | 视觉模型+录屏+前后对比 | 交付流水线 | ✅ 视觉评审(DeepSeek) + 对账 + 成本闸 |
| 知识沉淀 | — | — | 事件溯源 | ✅ 知识域 + 演进台账 + 记忆主干 |
| 护栏 | observe/30min | resource-guard | 跳数熔断/指令分离 | ✅ 全部有 |
| **差异** | 我们判定层更细；它们产品化/前端更完整 | | | |

**关键差异**：三个上游都是「先有执行/看板，再补判定」；我们是「先有判定（准入/清单/证据），再补协作」。所以它们强在「把活干完并交付」，我们强在「说得清谁负责、什么算对」。

## 3. 没做好的地方（诚实清单）

1. **多人真实协作是零**：准入/RBAC/会签/跨域委派整套判定层是为多人设计的，但只有龚哲一个真人跑过；许家豪/刘玉顺/林恒昌没进系统。
2. **codex 执行连不上**：本机 codex-cli 装了但调模型 `request timed out`（网络问题），执行暂时靠 DeepSeek 云模拟。
3. **委托链没融进执行链**：`agent-delegation` 是纯函数 + `/do` 命令的 fire-and-forget，还没接进 `collaboration-intake → loop-pump` 的正式派活执行链。
4. **录屏未解码**：`video-chapters`（LobeHub 的录屏章节标记）没做，验收的「录屏」证据还是名义上的。
5. **前端是单页 console**：功能靠 API + 一个 `app.js` 渲染，没有 LobeHub 那种「活文档 + 参数联动 + 多角色界面」。
6. **多机一致性(V7)**：`.runtime` 单机，主题/产物/巡检没做多机共享。
7. **两条执行路径**：`step` 模式和 `legacy` 模式并存（loop-pump 双实现），有维护成本。

## 4. 前端状态

- **现状**：`console/app.js`（单页，7 视图 × 2 主题 × 2 宽度 = 28 单元验收矩阵，之前全绿）+ `topic-workbench.ts`（自包含 HTML 活文档，独立打开，未集成进主 console）。
- **缺**：① 主题/委托链的界面（现在靠 CLI）；② 多角色工作台（coordinator/worker/checker 各看各的）；③ 协作链的实时进度视图。
- **对比**：LobeHub 是完整产品（84k star），我们是一个「够用的内部控制台」。

## 5. 结论

- **强项**：判定层（准入/决策/会签/跨域/知识域）+ 护栏（指令分离/熔断/成本闸）——这些是同类项目里最细的。
- **短板**：① 前端产品化；② 多人真实落地；③ 协作链融入执行链（刚开 `/do` 这个头）。
- **建议优先级**：先把协作链从 `/do` 命令扩到「飞书自然语言自动触发」→ 再拉 3 个真人进来跑一次多人交叉协作 → 最后补前端工作台。
