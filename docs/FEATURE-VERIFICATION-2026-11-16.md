# 逐项验证与端到端复跑

2026-11-16 · 对应[产品功能与架构清单](PRODUCT-CAPABILITY-MAP.md)的 25 项。验证结果区分真实外部交互、浏览器隔离实例、后端回归和沿用的历史实跑。当前验证范围为独立测试项目和授权测试仓。

## 完整业务流程

**自定义 CI 真实交付**。真实飞书测试群发起「门店推荐理由」小屏任务，维护人确认归属与仓库，原飞书研发账号点击接单。Codex 在独立工作区只改 `collab-pilot/index.html`，平台记录提交 `089316b4900021be445fc80f56a47101aac1b2d2`，实际推送并打开 PR #19。测试基线的必需检查配置为 `store-mobile-layout`，GitHub Actions App ID 为 15368。工作台核对该提交的成功检查，拒绝缺少证据、错误 SHA 和非发起人验收。用户从原飞书话题验收第 1 版。接单、执行和验收各一次，重放接单与验收的真实回调没有新增记录。Playwright 另验证 360px 下连续 70 个字母会折行且页面无横向溢出。PR 保持开放，测试仓未合并或部署。

**工作台入口与出处**。在隔离工作台用受控的飞书输入触发待确认，浏览器操作真实后台接口。选择授权仓库后仅显示有交付资格的 Agent。关闭再打开会保留草稿，直接提交不合格 Agent 被服务端拒绝。确认只生成一张代码单，处于等待研发接单。用此前真实文案、小屏和知识回用数据验证工单及知识页的链接。两处均打开精确成果修订，PR / CI 指向保存的外部地址。被打回的文案第 1 版显示本版的打回状态，错误修订显示找不到该版本。390px 下执行键盘跳转并核对无页面横向溢出。

**验收、回流与复用**。本轮新 PR #19 验收后形成候选。知识回流复用此前已由人采用的两条口径，读取真实执行快照、用量和引用记录。验证新单确实用了文案第 2 版与小屏第 1 版。小屏规则可追溯到 PR #18 的原提交与 CI。文案第 1 版只在原单历史。浏览器的出处来自后台提供的验收快照。

## 本轮新发现

- 服务重启时，通知可能在飞书卡片订阅就绪前退成纯文本。现在有卡片计划的待办会保留投递并重试。已经发送纯文本且已恢复为可办理状态的代码验收，在再次核对交付时补发一张原话题卡。
- 通过历史链接看第 1 版时，页头曾沿用当前第 2 版状态。浏览器测试改用第 1 版被打回、当前第 2 版已验收的真实历史样例，现按所选修订显示状态和执行归因。
- 交付状态和 CI 台账迁移曾各自硬查默认名称。现在交付状态使用与验收相同的检查选择器，以同一提交、App、检查名和最新重跑作门槛；旧快照回填保留已登记的同 SHA 检查。默认配置继续适用已有仓库。
- 下一轮优先核对只读新版选设备、Figma 真凭据实跑以及部署版本验收。另需覆盖生产多团队的并发、运维恢复和组织权限。

全量回归 62 项通过，1 项 Linux 专用测试在 macOS 跳过。类型检查、前端构建和上游锁定校验通过。
