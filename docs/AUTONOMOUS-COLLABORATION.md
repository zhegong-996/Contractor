# 自主协作运行合同

2026-11-05。用户提供的事件 → 协作控制 → 上下文 → 执行 → 证据 → 人的讨论/决定，作为本轮主链路。此前的整理器禁止所有工具调用，只产一份 JSON，不能代表自主协作已经整合。

## 职责划分

- SuitMe 定义个人服务、职责、事件关联、输入范围、关键决定和面向人的工作界面。
- Paperclip 统一原生任务、身份、签出、运行锁、并发、文档修订和人工审阅。没有新增第二个任务调度器。
- Super-agent 固定源码的 `settingsPolicy` 门控当前委托，`assessmentOutcome` 核对规则覆盖、需求意图、方向与设计决定。未启动独立 DSH Ticket 引擎。
- Autoloop 固定源码的 `createWorker` 真正承担进程执行、会话接续、原始输出落盘、回执解释、停止进程组和回传重试。协作与开发执行均使用它；不启动独立 Autoloop hub。
- DeepSeek Harness 的输入保留与序列化、Prime Agent 的检索词与近期目标权重继续运行。Cognee 提供当前可用的字典、图存储与读取能力。

SDK 负责 MCP 协议和宿主 UI 接口，业务判断、权限和执行闭环可在本仓库审阅。没有用 SDK 引用数量替代功能验证，也不为减少 import 而重写原版引擎。

## 一轮执行

1. 任务已有人的委托，或通过已登记服务明确发起。只接受当前公司、来源与身份边界内的事件。
2. 收集当前任务、资料、已关联交付的有效变化，按原生输入修订合并；机器进度不重新成为需求。
3. Paperclip 启动原生 run。Autoloop worker 取得这个 run 唯一绑定的工作，不从另一套任务库抢单。
4. Agent 读取上下文，核对来源，向 Super-agent 原版策略提交范围判断。可按证据动态检索、读记录、扩展获准片段和准备申请；范围判断不通过就不能提交准备成果。
5. 交付前重查目标、来源修订、权限与职责版本。原文引用必须逐字存在于本轮输入；模型不能自批授权、采用知识或验收。
6. 工作稿和检查点进入原生私有修订。需要人时保存具体问题并结束进程；回答或许可变化后，接续同一业务任务。
7. 开发结果经固定路径检查后更新同一 PR；CI 和预览匹配提交 SHA。人保留真正的审阅归属和验收权。

## 工具边界

`read_context`、`assess_scope`、`search_context`、`read_record`、`discover_context`、`expand_context`、`request_access`、`read_graph`、`discover_services`、`read_execution_evidence`、`schedule_recheck`。任务、run、执行身份由服务端绑定，参数中没有切换身份、任意命令、批准权限、合并发布或最终验收的入口。

每轮最多 12 次工具调用；长资料扩展沿用最多两份限制；每次明确委托最多两次定时复查。资料拒绝或撤权后不重复申请，等人时不轮询催促。变更目标、职责、资料或权限后，旧结果不能伪装为当前结果。

读取既有证据包括带代码指纹的真实测试用例结果，及已明确关联的同 SHA 交付文件；文件名、读取预算、版本和哈希由服务端核对，不能借此读取任意工作树文件。

原版 worker 先保存结果再回传。回执格式或响应丢失不重新执行业务。进程状态未知时保留原工作树与执行日志，核实停止前不启动替代写入。

## 本轮真实验证

- SUI-74 是本次实际平台升级的审阅清单任务，使用实际架构记录及运行反馈；没有载入旧 B2C 私有原文。
- 首轮实际工具调用包含上下文读取、原生记录读取、范围判断和知识检索。首次规则判断被拒后，Agent 自行纠正并完成合法判断，生成两份待审阅稿及检查点。
- 后续反馈进入同一任务，自动启动下一轮并生成增补稿；没有新建另一件业务任务，也没有自动采用知识或最终验收。
- SUI-81 通过原版 worker 完成真实代码改动并交付测试仓库 PR #3。过程中发现原生审阅归属约束、非网页成果不能通过旧 HTML-only CI 两个集成问题，按原任务和分支恢复，不重跑已完成的业务进程。
- 原版 worker 进程测试覆盖重建、丢失一次回执响应后仍只启动一个业务进程。版本、权限、预算、规则范围、职责版本与文件预览另有回归检查。

具体最新提交、CI、预览和本机截图保存在验证记录。通过代码检查不等于员工协作网络、生产发布或业务效果已被验证。原始输入、回复和执行日志仅保留本机 `.runtime`。
