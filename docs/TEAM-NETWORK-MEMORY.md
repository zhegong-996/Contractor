# 多人服务协作与团队知识记忆

2026-11-05。对照用户提供的玉伯访谈，直接适配原生组织身份、服务委托与持久知识。用户继续选择不启用新的模型服务，因此本轮使用既有 Codex CLI、Cognee BM25 和有原文依据的人审概念关系，不启用新增 LLM/embedding 服务。

## 开源复用与产品责任

| 来源 | 实际运行的能力 | SuitMe 的适配 |
|---|---|---|
| Paperclip 固定源码 | 成员、邀请、公司角色、私有项目、任务、签出、运行、文档修订、授权与原生人工审阅 | 真实成员到独立 Agent 资料身份的绑定、资源负责人操作范围、人的实际归属和审计 |
| 官方 `@a2a-js/sdk` 1.3.0 | `DefaultRequestHandler`、`JsonRpcTransportHandler`、`TaskStore`、`ServerCallContext`、任务/状态/成果协议与取消 | 同一原生父任务及服务子任务的持久映射；查询时从当前原生状态重建，不新建调度器 |
| Super-agent / Autoloop 固定源码 | 范围判断、事件接入、真实 worker、回执、等待与进程恢复 | 服务调用仍通过现有受限工具与原生运行，不用 HTTP 接口数量代表自主性 |
| Cognee 固定 1.6.6 | DataPoint、Ladybug、来源追踪、内容衍生 chunk ID、原版 BM25 语料统计和评分、GraphSchema 与图谱渲染 | 来源修订与字典修订隔离、权限过滤后的语料注入、当前范围复查、概念关系候选与人审 |
| Prime Agent 固定源码迁移 | 中文与多语查询分词 | 同一分词用于实际 chunk、概念及查询，不另造检索评分算法 |

A2A SDK 是实际接单、状态、回传和取消链路中的运行代码。其存储端口指向 Paperclip 文档；状态投影不保存原文或成果正文，避免成为撤权之后仍可读取的旁路副本。服务成果只在双方当前权限允许时动态返回。

## 人与服务 Agent

成员身份来自 Paperclip 原生登录及 active company membership，不能填写任意 userId 冒充成员。管理员从真实在职成员目录开通新的独立资料身份，复用 Paperclip Agent/Key API 与原生 metadata 恢复中断；不授予任何项目或知识访问。已有身份迁移收在高级设置中；两个成员不能绑定同一个身份，旧身份保留归属记录，换绑后不能变成无主凭据继续访问。读者角色不能通过适配层获得写入能力。普通成员不能修改模型服务、全局配置、其他成员的服务或他人的任务，也不能批准自己向其他资料负责人提出的访问申请。

服务目录保持个人/公共服务、当前职责与版本；成员停用、归属或职责改变会阻止继续使用旧委托。知识空间与职责名称可配置，不以产研、增长、销售、职能划定固定系统边界。原生人工审阅跟随真实任务发起人，不固定给 local-board。

### 从飞书进入

已登录成员可以在“Agent → 成员与归属”生成五分钟、单次有效的配对码，自己在机器人单聊发送。原版 Super-agent 解析真实 sender 与 chat，配对记录只绑定当前登录成员，不授予资料访问。重复投递可以恢复，另一个 sender 不能复用；被停用成员不能继续配对或使用原绑定。原有试点用户白名单继续可用；新成员配对不会扩大旧开发机器人 `/task` 的全局白名单。

### 委托、澄清与回传

1. 负责人选择服务、核对职责版本，确定交接目标和资料引用。服务不会因接单获得资料权限。
2. 当前 Agent 可按这个范围调用 `delegate_service`；没有已明确范围不能任意转发上下文。相同交接复用同一子任务，每个父任务最多三项委托，本轮不递归转委托。
3. 服务 Agent 用自己的身份读取资料；资料缺失仍走原有申请和负责人批准。`ask` 结束本轮，释放执行。
4. 人可以明确补充交接内容；Agent 只能用双方仍有权、且已列入交接包的逐字原文回答，最多三轮。
5. 子任务回传工作稿和问题，父任务自动接续。成果依赖跟随子任务的当前运行、职责、来源与权限；旧回传不能在新版本中继续冒充当前结论。
6. 父任务停止或结束会停止未完成子委托。原生运行继续负责真实进程停止，界面区分正在停止与已取消。还有服务在执行时，不提前催促最终验收。

原生审阅、知识采用及最终验收仍是人的决定。协议的 completed 表示该轮服务已返回成果，不代表业务任务已经验收。

### A2A 端口

本机已有父/子委托可使用 `POST /a2a/<parent-id>/<child-id>`，通过当前调用身份的 bearer token 认证。使用官方 A2A 1.0 / JSON-RPC 2.0 实现，开放 `GetTask`、`SendMessage`、`CancelTask`；发送限制在负责人已明确的交接包，重试不重新派单。不能通过 RPC 扫描其他任务、修改目标、设置远端推送或切换身份。当前未开放公网服务发现或任意远端 Agent 注册。

## 知识的持续积累

已确认知识按当前来源修订生成持久 chunk、字段和图关系；既有后台检查每轮推进一份待建索引，不增加另一个调度器。未确认工作稿、已撤回/过期知识和外部飞书原文不自动进入这个索引。任务中的新工作仍先生成候选，再由人确认和采用；不是把所有聊天永久记忆化。

检索先确定当前成员或任务的实际范围，再将获准的版本图交给 Cognee 原版 BM25。语料同时包括正文 chunk 和已采用的概念/关系原文依据。返回有来源、修订和分数的引用；交付前重查来源 hash、过期状态、字典、原生权限和成员归属。命中可以查看来源或加入当前任务；加入引用不等于已授权 Agent 读取。

概念与关系由既有 Agent 使用 `read_memory_dictionary`、`propose_memory` 准备，要求逐字原文依据、有效关系端点及当前字典类型。人审的是确切候选修订；源文或字典变化后必须重整。人采用后形成新的物理图版本，撤回后当前检索不使用旧关系。跨来源结果按各自证据返回，不把相同名字自动合并为全公司共同事实。

本轮不是向量语义检索或自动 LLM `cognify` 管线。配置和代码没有擅自启用新模型服务，也没有把词法分数称为语义理解置信度。

## 前端信息架构

- 我的工作：人的待决事项、正在等待的服务、可审阅成果与最近沉淀。
- 协作：任务与访问申请；任务内有进展、上下文、协作与交接、知识沉淀。服务委托在前，变更当前任务负责人收进高级交接。
- 知识：检索与记忆、内容与图谱。内容、类型字段、来源版本、图谱与字典保持同一知识对象；空间是可配置数据，不是固定岗位菜单。
- Agent：服务目录与成员归属。先找人提供的服务，负责人的职责设置按需展开；Codex 等执行身份与服务名称分开。
- 设置：模型、服务状态、空间与权限。日常知识页面不重复展示底层身份同步配置。

## 部署与验证边界

当前实例仍为 loopback 的 local_trusted 模式。多人登录能力复用 Paperclip 原生 authenticated 部署、成员邀请和登录，不另造账号系统。切换之前必须配置原生管理员账号及后端服务身份；适配层支持通过 `COLLAB_PAPERCLIP_BOARD_TOKEN` 使用原生受控 board API token。执行子进程不会继承该变量。没有在用户未建立管理员登录的情况下强行切换并锁住现有后台。

当前真实服务联调是本机同一负责人下两个实际 Agent 资料身份的委托与回传，不是两位真实员工登录的生产验证。成员隔离、停用、只读角色和防冒用通过隔离工程用例验证；实际团队成员仍需通过页面中的原生邀请与归属完成入驻。

真实已有知识已经完成持久索引与跨进程检索。另用明确标识的隔离工程资料验证 Cognee 概念、中文关系、非原文别名检索及进程间持久化；工程资料不进入业务知识库。私有运行证据均在忽略提交的 `.runtime`。

## 读取与执行的响应性

页面只读查询不排在索引和原生执行检查之后；写操作、工具回执与接单仍使用唯一串行通道。原生文档修订和 ACL 仍各自重新核对。当前请求中的共同依赖只验证一次，后续请求重新验证，避免多轮交接形成分支依赖后指数增长；循环依赖仍拒绝。没有跨请求权限缓存。
