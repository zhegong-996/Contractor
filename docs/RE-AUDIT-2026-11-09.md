## 1. 结论先说

**核心闭环是真的**：接单 → 自有权属下干活 → 拿不准发卡拍板 → 点了接着干 → 逐项验收 → 打回记忆回流，六个环节都能在代码和现场找到证据。

**上一轮"全部实现"这句话说过满了**，本轮修正两处：

1. **功能面**：核心闭环全通，但周边还差 3 类（规则匹配与并发、GitLab/HTTP 事件源、验收的区域框选与主题矩阵）。这些不是遗漏，是此前没进清单。
2. **运行面**（更要紧）：上一轮验收时 bridge 是临时跑起来的，**没有常驻**；而且后台主循环存在单点故障 —— 一个 Paperclip 侧已不存在的交付任务就能把 `scheduler` 和 `github-watch` **饿死**，日志里刷了几百条同样错误。也就是说：**当时"定时调度器已实现"只在代码层成立，在运行层不成立。**

本轮把运行层 4 个缺陷修掉，并补了 cron 排班。现场复验：调度器两条例程在线（晨报每天 09:30 / 每周日 18:00 整理），唤醒预约仍在册，GitHub 监听在轮询。

### 常驻安装的本机限制（如实）

`npm run service -- install` 在本机报 `Bootstrap failed: 5: Input/output error`，用最小 plist（`/bin/sleep`）复现同样错误 —— 当前会话环境不允许创建 launchd 任务，不是 plist 写错（`plutil -lint` 通过、plist 已落在 `~/Library/LaunchAgents`）。
**需要在「本机普通终端」执行一次**：

```sh
cd ~/Developer/ai-native-collab && npm run service -- install
```

之后 `npm run service -- status` 应显示 `launchd=running`；卸载 `npm run service -- uninstall`。
