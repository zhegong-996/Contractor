1 · 产品主闭环：从一句中文指令到人签验收

产品视角 / 业务视角

官方口径是 8 步、4 个人工决策点，这里合并成 5 个阶段便于一屏读懂。琥珀色标记「人必须做决定」的位置，蓝色是系统可自动推进的部分。

怎么读：4 个人工决策点分别是定职能责任、跨空间授权、锁定验收清单、最终核可。Agent 完成 ≠ 业务验收——报告、模型判定、CI 通过、合并审批都不替代最后一步；SUI-129 至今未核可。每条链上的证据由 trace-view 提供。

2 · 用户与界面：谁在哪儿做什么

用户视角 / 职责边界

看起来有多个界面，但只有一个能发起任务。工作台和控制台是处理与观察面，MCP / CLI 是给 Agent 的接入面。

怎么读：琥珀色只有一块，就是唯一发起入口。控制台的白名单全是只读动作，密钥不出服务端；「没连接不要放空入口」是前端硬约束，未接通项连 URL 字段都没有。

3 · 技术四层架构：端口、协议与唯一真源

技术视角 / 分层与数据流

自上而下是入口、接入、业务核心、本机与宿主。两条不可绕过的约束写在图内。

怎么读：身份链（插件 worker 取宿主不可变 context.actor，带 token 打 Bridge）保证 UI 参数不能指定操作人；任务不双写（Paperclip + PostgreSQL 是唯一任务 / ACL / 文档修订真源，本地 SQLite 只做事件去重、回执、审计与投影）。Trace 写入是 advisory，失败不改业务结果。

4 · 共享记忆分层：知识必须能查回事实源

技术视角 / 知识与治理

越往下越接近事实，越往上越小、越接近每轮上下文。这是 P-7 参考 Anthropic 分层、P-8 补上只读接线后的现状；P-9 把双向协作回路的留痕接进三个真实执行链节点，P-10 修掉回路判据的五个真实缺陷并把飞书显式「回答」路由进成对台账；只读 loop-guard 与 memory-guard 并列。

怎么读：底层 .runtime/memory/events.jsonl 与路由留痕是 system-of-record，四类投影（L1 证据图 / L2 组织图 / BM25 向量 / Context Pack）只是它的投影。撤权是状态写入不是物理删除；source-revoked 全局阻断、grant-revoked 按主体精确排除。P-8 的 memory-guard 是只读体检，真实 22 条知识记录缺事实源挂靠时如实报缺口，不编造事件 id 把体检跑绿；P-9 的 loop-guard 同样如实报 bidirectional:false 与四个耦合点计数 0（真实业务单尚未在该链跑过），不编造事件跑绿。

6 · 成熟度三档与不可冲掉的红线

成熟度（决定「能不能对外说已支持」）

  • 已跑通且有回归证据：发起 / 派单 / 上下文与知识 / 验收 / 交付 / 治理主干 + B1 / B2 记忆 + 11 步真实浏览器走查 + 全套隔离真跑；当前 npm test 532/532、loop:smoke 16/16、guard:smoke 22/22。
  • 预备配置，不等于启用：模型三档策略（不存 Key）、L2 组织图草稿（人审后生效）、飞书部门 scope 授权命令、组织映射草案、step 模式与 local-pg 底座。
  • 未接通 / 未发生：企业微信 / 腾讯文档 / 钉钉 / 国内代码托管 / 公有云 CI / 海外 SaaS、全员 SSO 与真实员工入驻、生产发布、真人在真实业务单确认验收（SUI-129 未核可）、外部模型调用、远端沙箱与金额成本账本。

红线

  • Paperclip + PostgreSQL 是唯一任务 / 成员 / ACL / 文档修订 / 审计真源，SQLite 只做映射、幂等与接入投影。
  • 默认隔离、按用途放宽：临时授权绑定「本任务 + 指定执行身份 + 期限」，可撤销；权限挂数据上而不挂身份上。
  • 资料授权、知识采用与撤回、最终验收由人决定，模型不得自批；Agent 完成 ≠ 业务验收。
  • 制品状态（草稿 / 已验收 / 可复用）与验证等级（L1–L4）是两个独立维度，不合并成一个字段。
  • 运行时状态、凭据、真实姓名与 open_id 只落 .runtime/ 不进仓库；Trace 写入失败不改业务结果。
  • 不引入第 8 个上游；未接通的服务不放可点入口；4190 / 4192 / 4194 / 9418 保持停机。
