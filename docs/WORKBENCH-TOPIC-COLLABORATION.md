# 主题内协作

项目结构里的主题名称打开该主题的讨论。成员可以普通发言，也可以选择一个或多个已授权的 Agent 发起只读咨询。同一条咨询下面显示各 Agent 的署名回复、执行记录和精确出处。主题上方保留相关业务工单入口。

飞书成员在已绑定主题的群里发送 `/咨询 问题`，也可先点名机器人。启用卡片回调和 `workbenchPublicUrl` 后，同一飞书账号的待办汇总到一张「Contractor · 待处理」私聊卡，按项目和主题分组。需要选择 Agent、接单或验收时，系统更新这张卡。重复点击沿用同一次咨询。原有 `/咨询 @wrap-codex 问题` 快捷方式仍可使用。

已配置固定话题的结果卡回到该主题对应的飞书话题，默认只显示处理状态和工作台入口。配置 `workbenchPublicUrl` 后，成员登录即可打开对应回复、正文及出处。维护人可在可信配置中对指定的飞书群资源开启 `shareConsultationResults: true`。群须在允许名单中、绑定对应项目主题且启用咨询，只有资料和上游均满足项目共享权限时才可随群卡展示结论、来源及可用的 PR、CI 链接。工作台与 GitHub 原页继续各自鉴权。

## 项目配置

在项目的飞书群资源上配置 `feishuTopicRoots`，例如 `{"reasons": "om_example"}`。键是工作台主题 ID，值是同一个已绑定群里预先确认的飞书话题根消息 ID。子主题没有独立入口时可沿用其父主题入口。同一个话题可以讨论多张工单，续单依靠具体引用，话题入口本身只确定主题。当前配置从新消息生效，飞书已有话题继续保留原记录。

群的普通入站归属默认项目。可在该群资源配置 `feishuSubprojectRoots`，用飞书根消息 ID 精确指定直属子项目和主题，例如 `{"om_example": {"project": "pilot", "topic": "review"}}`。要启用该入口的断线补读，在同一个映射中加 `recovery.thread` 与 `recovery.reader`。前者是原飞书话题 ID，后者绑定已授权的子项目维护人和飞书读取身份。补读使用该子项目的独立话题游标，只关联已引用到同一子项目现有工单的普通回复。它不执行开单、咨询或答题命令，也不进入上级项目的群整理。群成员仍能看到公开入口及在群里主动发送的消息。子项目工单回执和结果留在工作台及本人待办，系统不回写到共享群。需要私密讨论的子项目可绑定自己的群。

个人待办卡显示本人有权查看的项目路径及主题。关联工单的待办还提供工单入口，父单和子单沿用工作台里的关系。验收按钮显示对应的工单短编号。受限工单以编号显示，打开后由工作台重新核对权限。调整工单主题时，待办在同一张卡上按新主题显示。

在实例 `workbench.json` 的项目里配置 `consultations`。知识 ID 使用项目中已采用、项目成员可见的条目 ID。来源被撤权或失效时暂停使用。Agent 可以承担任何项目职责，配置示例使用两个专业方向。

```json
{
  "consultations": [
    {
      "topic": "reasons",
      "feishu": true,
      "agents": [
        { "agent": "copy-claude", "material": ["copy-knowledge-id"] },
        { "agent": "wrap-codex", "material": ["layout-knowledge-id"] }
      ]
    }
  ]
}
```

打开 `feishu` 表示允许该项目的已配置群接收这些咨询回复和来源。群的讨论来源须绑定到同一个主题。只有飞书账号已绑定的项目成员能发起。咨询可见资料及其上游必须都是项目共享状态。源站链接继续以源站权限为准。工作台发起的咨询保存在主题内。

每条咨询对同一个 Agent 只创建一次委托。同一飞书消息再次送达或工作台重试同一次提交，沿用已创建的记录。Agent 通过 AutoLoop 的只读执行路径工作，挂载资料和返回来源分别校验。没有可核对引用时显示受阻，并保留执行记录。咨询成果不进入交付验收和知识候选。需要代码改动时，成员可打开已有业务工单续版，或在主题发起工单并选择交付仓库，研发接单门槛继续生效。

项目可在可信配置中启用 `consultationHistory`，字段为 `profile`、`appId`、`userOpenId`、`member`。读取身份必须属于项目维护人，并能读取已经绑定且启用飞书咨询的群。同一项目无需开启普通群消息整理。订阅重连及定时补读使用已有游标和近期已知话题。补读复用实时咨询的项目权限、账号校验和消息去重。直接点名的请求按原消息补派，未点名的请求由提问人在待办卡选择 Agent。跨飞书应用的 Open ID 只有经过账号绑定，或属于该配置指定且已验证的读取者本人，才能对应到机器人的项目账号。首次启用时从启用时点接管，历史查询窗口沿用三天上限。

若 Octop Gateway 或 Memory 在咨询补读时暂不可用，保留受影响的群或话题游标，下一轮重读时沿用原消息 ID。同一批可正常处理的事项仍可落库。检索正常返回无匹配资料时结束该次咨询检查，游标可以推进。

群内咨询结果卡可见范围由飞书群决定。工作台完整回复、业务版本和知识按项目权限读取，PR 与 CI 原页由 GitHub 单独鉴权。

如果咨询引用了当前已经验收的代码版本，原发起人可从「查询依据」点击「按此咨询开启原单下一版」，填写修改范围并请研发接单。新版记录咨询成果修订与原验收版本。研发接单绑定这次委托和业务版本，上一版的接单和 CI 都需要保留在历史中。GitHub 证据核对后，发起人在原飞书话题验收对应提交。
