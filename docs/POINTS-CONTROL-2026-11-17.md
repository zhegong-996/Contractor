# 积分管控后端接入与实跑（2026-11-17）

本轮以现有测试工作台 `store-dual` 为对象，仅新建只读联调单。运行版本 `baef89509f93678b`。AutoLoop 仍是唯一调度器；积分层在原派工事务中校验和预留，在原回执事务中结算，没有另建调度器。

## 本次实现

1. 启用状态显性化：`GET /api/budget/points-status`；模型策略返回 `enabled`，每个池返回 `enabled/enforced/blocked/overLimit`。只改倍率的旧客户端不会意外重新启用已关闭的积分管控。
2. `provider + model` 匹配倍率；启用后未配置倍率的模型拒绝启动。每次执行冻结兑换率、倍率和预留，不随之后修改重算。
3. 超预留不丢弃真实用量：回执显示 `overReservation`，池显示超限；真实 Token 全量入账，任一适用池余额耗尽就阻止下一次执行。换模型或执行端不能改写计费所属项目。补额后需明确接续，不自动重跑旧单。
4. 未报告/部分报告用量保留未结清的预留；确认未启动可释放。关闭开关不免除已经预留的在途执行；启用前的历史执行不追扣。
5. 实跑发现只读接续误带代码模板：原需求被提示为仅供背景，轻量模型忽略了上下文文件。已把只读接续与代码改动分开，要求先读取 `task.request`，接续理由不能替代原委托。原失败输出与消耗保留。

## 现行测试配置

按北京时间每日归属，1,000 Token 为一个基准积分，向上取整到 0.001 积分。

| 模型 | 倍率 | 每次预留 Token | 每次预留积分 |
|---|---:|---:|---:|
| OpenAI / gpt-6-luna | 0.1× | 30,000 | 3 |
| OpenAI / gpt-6.1-sol | 0.5× | 30,000 | 15 |
| DeepSeek / deepseek-v4-pro | 3× | 10,000 | 30 |

测试项目总池 100 分/日；项目执行池 70 分/日；平台整理池 10 分/日；product、engineering 个人池各 10 分/日；项目内各 Agent 上限 30 分/日。倍率是本次测试配置，不是供应商价格。

同一笔消耗只有一个执行账目，同时被项目总池、该类用途池、项目内 Agent 上限约束，不是扣三遍。平台与个人池按主体跨项目共享，项目执行池及 Agent 上限按项目分开；子项目不自动扣父项目。
