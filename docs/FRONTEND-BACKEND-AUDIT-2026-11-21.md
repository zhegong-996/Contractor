# Contractor 前后端功能与业务流程审计

2026 年 11 月 21 日。以本地提交和现有测试台版本 **ba888df32f86** 为基准。

## 结论

1. **交付和验收已有完整的版本链。** 门店工单可以从看板进测试报告，查看当版截图、录像与 GitHub Actions，从失败用例打回后在原单继续。真实 PR #22 已从 280px 检查失败走到第 2 版验收。旧证据仍可查，签收和采用知识各有对应动作。具体工作台工单和私有测试仓证据保留在受保护的测试环境。
2. **新项目到第一张代码单的配置断在中间。** 浏览器能创建项目、加成员和建主题。交付仓、代码基线、写入路径和验收模板仍需部署配置。模型与执行端也有部署前置条件。用户先看到各个配置页，运行前仍得自己拼齐这些条件。
3. **当前门店测试项目已阻止新执行。** 项目总积分每日上限 100，已用 243.710、预留 45。项目执行池和小屏 Codex 也已超限。9 台登记设备中有 5 台启用，0 台在线。发起表单可以选择已有仓库和小屏 Codex，提交前看不到对应额度阻塞。这些数字是本次观测的环境状态。
4. **异常恢复和责任人交接有三处已复现的缺口。** 原发起人退出后待验收单失去可签收的人。后台查询暂时失败会退出设置页并丢草稿。两个旧额度表单可以互相覆盖。

## 各模块流程

### 1. 登录、身份绑定与平台角色

企业主 IM 授权回调核对应用与身份。已有成员进入原链接，新身份进入开通审批。平台角色、项目成员资格、知识授权和 GitHub 等源站权限分别核对。个人可编辑资料、绑定来源账号或按策略使用口令。平台管理提供账号审批、停用和会话撤销。 [登录接口](../src/workbench/im-login.ts) · [成员管理](../workbench/src/platform-access.tsx)

实测所有者可以打开平台和本项目设置。项目协作者读取成果和知识成功，平台管理与项目设置返回 403。项目外访问工单或知识返回 404。隔离实例中的只读成员也看不到发起按钮。测试台主登录采用飞书，保留口令作为补充方式。

### 2. 项目、子项目、主题和成员

平台授权决定能否建独立项目，维护人可以建子项目。创建者成为新项目维护人，再添加已开通的成员、确定读写角色、新建主题及上级主题、设授权有效期或移交维护权。子项目成员权限单独核对。项目结构汇集项目关系、主题、Agent 和近期工单。 [项目目录和权限](../src/workbench/project-directory.ts) · [项目设置](../workbench/src/access-settings.tsx)

隔离实例从前端创建了项目、主题和只读成员。新项目初始只有一位成员，资料、交付仓和 Agent 为空。现有界面以创建和查看为主，已建项目与主题的更名、归档和关系编辑入口需要补充。

### 3. 资料与连接

维护人在「资料与连接」绑群、关联文档或 Figma，确认已登记的 GitHub 仓库。「知识与记忆 → 接入资料」读取正文并生成候选，核对来源权限和版本后再采用。链接可访问、服务能读取正文、Agent 有写仓权限各自有条件。GitHub 文档固定到文件和提交，Figma 支持复核源权限与版本。 [连接页](../workbench/src/project.tsx#L101) · [来源读取](../src/workbench/knowledge-sources.ts#L52) · [资源契约](../src/workbench/project-resources.ts)

测试仓能显示同步状态和上次成功时间。隔离新项目的「关联资料」只有飞书文档、Figma、外部文档三类，交付仓及模板需部署配置。已关联资料的编辑、解除绑定和替换缺少入口。绑群候选直接显示部署者允许的群 ID。

### 4. 渠道接入、筛选与归属

飞书、GitHub、其他已部署 IM 的事件先登记来源和修订，再校验账号、项目、引用及去重。明确引用可挂回原单或主题，普通反馈可定时整理，歧义进入负责人待办。决定人选择项目、主题、原工单、新单或忽略。有权限的外发使用原会话地址并记录回执。 [入站](../src/workbench/intake.ts) · [渠道日志](../src/workbench/channel-journal.ts) · [归属分流](../src/workbench/channel-workflow.ts) · [群反馈](../src/workbench/discussion-workflow.ts)

测试台飞书消息、卡片回调和 GitHub 同步均就绪，飞书积压为 0。一条额外 IM 连接未就绪，通知外发暂停。重放、补读和多通道恢复由现有自动回归覆盖，本轮主要核对了入口与运行状态。

### 5. 发起协作、任务中心与待我处理

从工作台或项目主题发单，选择范围、主题、Agent 或职责、资料和验收条件。代码单加选交付仓。后端检查项目、父单和目标仓权限，并用请求标识处理重试。明确任务进入工单，职责歧义进入待办。任务中心按范围、主题、状态和文字筛选。待办指向相关人、工单、版次与处理动作。 [发起表单](../workbench/src/creation.tsx) · [任务中心](../workbench/src/work.tsx) · [待办](../workbench/src/inbox.tsx)

门店表单可选现有交付仓与六个合资格 Agent，显示三项自动检查和一项人工核对。各相关积分池无余额时仍可提交。新项目缺少合资格仓库时，「代码交付」整区隐藏，缺少配置入口。看板搜索后进入已验收工单，查实测图并返回，搜索词仍保留。

### 6. 项目讨论、Agent 咨询与个人会话

个人会话使用本人的个人 Agent 配置，保存对话记录。项目会话聚合已关联的项目、主题和工单消息。咨询发出前选择获权 Agent 与设备，结果回到讨论并保留执行和引用链接。工单留言留在工作台，公开回复动作把内容发到允许的原飞书会话。会话归档作用于自己的目录。 [会话目录](../workbench/src/conversation-directory.tsx) · [项目会话](../workbench/src/conversation.tsx) · [个人会话](../src/workbench/personal-conversations.ts)

浏览器已打开个人和项目会话、历史及来源入口。个人聊天需要已接通的模型。页面同时使用「个人 Agent」「成员执行 Agent」「我的 Worker」，首次配置时需要理解这三者的关系。

### 7. Agent、平台整理模型与共享专家

项目 Agent 按部署注册、所有者与项目授权进入目录，可查看职责、任务、知识与回执。个人 Agent 可配置轻量模型、个人指引及经验。平台「Router 与知识提炼」配置生成路由建议和知识草稿的模型，建议由人确认。在专家库可建只读专家、共享、复制模板、挂载或卸载技能版本。 [Agent 目录](../workbench/src/agents.tsx) · [模型设置](../workbench/src/agent-settings.tsx) · [专家库](../workbench/src/agent-library.tsx)

上述配置页和专家库均可打开。执行 Agent 的隔离引擎、模型凭据及受信执行路径由部署者配置。平台「模型服务」保存供应商执行政策和模型范围，运行时仍会检查引擎、凭据和设备。

### 8. 项目职责、牵头人与选择规则

维护人在「职责与路由」配置成员职责，按主题、上级主题和项目范围安排牵头 Agent、决定人以及主备模型和设备。后端按范围与规则选择合格执行者。缺少唯一候选时发待办，平台整理模型可以提供建议。配置保存时核对修订。 [选择规则](../src/workbench/router.ts) · [配置校验](../src/workbench/operations-settings.ts) · [配置界面](../workbench/src/operations-settings.tsx#L160)

门店项目显示两条主题牵头规则，主备模型区为空。默认执行端显示「按现有执行端配置」。页面缺少查看某类工单会命中哪条规则、用哪个设备，以及为何回退的预览。

### 9. Worker、执行、重试与交接

从「我的 Worker」登记本机或远端设备，确定所有者和项目范围。发单或项目规则选择设备，领取前复核当前权限、运行能力和额度。调度器保存租约，Worker 按执行尝试回报启动、实际模型、成果、用量和停止。断线时等待原端或找人核对，确认旧执行停止后才切换。跨账本写入失败可按原回执补写。 [Worker 协议](../src/workbench/remote-runner.ts) · [交接和接续](../src/workbench/handoffs.ts) · [执行回执](../src/workbench/execution-receipts.ts)

测试台运行 Contractor 调度器。登记设备在审计时均离线，历史执行记录可读。代码产出依赖受支持的 Codex 隔离路径。CLI 已配置、设备已登记和引擎能接单对应不同状态。当前「在线」「暂停」「离线」提示仍需配合引擎、凭据与任务范围判断。 [运行能力](../src/workbench/execution-capabilities.ts) · [连接手册](WORKBENCH-REMOTE-RUNNER.md)

### 10. 上下文、受限授权与子任务

工单范围、已确认的问题、主题依据、资料版本和写入限制组成执行快照。受限资料按工单、Agent、修订及有效期核对。缺权限时向资料负责人申请。接续、换端或撤权后重新核对，历史快照按当前权限展示。子任务各有范围、版本和回执，父单只用当前仍有效的子任务成果做汇总。 [上下文](../src/workbench/execution-context.ts) · [知识权限](../src/workbench/knowledge-authority.ts) · [子任务](../src/workbench/delegations.ts)

浏览器可切换当版和历史的执行快照。资料撤回、换端和对派生成果的影响由自动回归覆盖。资料、设备和设置的跳转入口分散，容易在处理中离开原单。

### 11. 模型用量、积分与额度

平台管理员调整换算基准、模型倍率和平台或个人积分池。项目维护人调整项目总、执行及项目内 Agent 额度。领取前同时核对各池并预留，回执按当轮倍率计账。状态区分已测、部分回报、未回报和未启动。超额使用按实际记账，随后受额度约束。旧记录不追扣。 [积分账本](../src/workbench/token-points.ts) · [项目额度 API](../src/workbench/collaboration.ts#L4659) · [额度界面](../workbench/src/agent-operations.tsx#L80)

门店额度页能显示「暂停新执行」与待完整回报轮次。阻塞原因在发起前不可见。当前工单的恢复提示还缺少直达对应额度和责任人的入口。隔离实例的双标签页旧额度编辑会覆盖新值。

### 12. GitHub 交付、CI 与部署证据

代码委托冻结仓库、基线、写入路径、受托研发和模板。Worker 回传改动后由平台校验范围并生成受托提交。交付人员把该提交推送、开 PR，再关联工单。同一 PR 的后续提交经同步匹配，核对本版提交、目标仓、基线和对应的必需检查。启用独立审查或部署门禁的单还要核对相同版本的附加证据。 [工作树与提交](../src/workbench/development.ts) · [交付证据](../src/workbench/delivery-evidence.ts) · [配置手册](CONFIGURATION.md)

PR #22 的两版提交、CI 和最终验收已有真实记录。上轮实跑使用命令推送受托提交，经 GitHub 接口开 PR，再关联工单。工作台提供关联、核对和跳转。执行结束到 PR 创建之间的操作人和时限需要项目约定及工单内提示。

### 13. 测试报告、按版本验收与打回

工单「测试与验收」读取冻结的模板和本单人工项。后端按仓库、SHA、固定工作流及 CI 尝试记录用例、截图和录像。发起人可以核对人工项、从失败项打回并开原单下一版。最终验收再次检查版次、资料可用性与 GitHub 证据。 [测试报告](../workbench/src/work-verification.tsx) · [CI 证据接入](../src/workbench/github-product-verification.ts) · [验收校验](../src/workbench/ticket-acceptance.ts#L46)

门店第 1 版为 228px 并已打回，第 2 版为 244px 并已验收。切换版次可查看各自的证据。错版请求与项目外访问均已拒绝。隔离补测发现原发起人退出后，接任维护人可读成果，验收无法转交。附件请求失败时缺少就地反馈与重试。

### 14. 知识采纳、版本与复用

工单验收后形成知识候选。负责人核对正文、范围与来源，可用轻量模型提炼，再决定采用或替换。知识页展示现行、待确认、历史、来源关系和使用记录。后续工单只装配当前允许的知识。过期、撤权、来源丢失和知识替换分别影响检索与成果显示。 [知识界面](../workbench/src/knowledge.tsx) · [知识版本与来源](KNOWLEDGE-VERSIONS.md)

已打开知识目录、关系、协作沉淀和授权页。查看来源状态、采用正文、处理工单临时授权需要进入不同位置。知识候选如果能直接说明卡在哪一环、由谁处理，使用者可以少做一次跨页判断。

### 15. 回归评估与业务观测

维护人从已有成果版本建立回归用例，用同口径的成果或检测证据做对照。结果保留版本、模型、手段和实际发现。验收后发起人可登记指标实际值及证据，把经验作为后续工单的基线。 [回归页面](../workbench/src/project-regression.tsx) · [回归评估代码](../src/workbench/regression-review.ts) · [业务观测](../workbench/src/work.tsx#L707)

回归页面可达，对照与验收快照有自动化覆盖。当前对照使用已存在的结果，回答检查采用字词和引用规则。自动重跑、定时对照和发布门禁是独立的能力缺口。

### 16. 运维、恢复与部署

平台「服务状态」展示渠道、索引、入站积压、回执补写、插件和通知设置。「权限记录」追踪账号与配置动作。备份、恢复和更换调度器通过部署命令执行。业务与调度账本分别保存，实例有状态目录租约。 [服务页面](../workbench/src/operations-settings.tsx#L118) · [账本备份](../src/workbench/ledger-backup.ts) · [调度迁移](RUNTIME-MIGRATION.md)

工作台进程就绪，集成健康因额外 IM 未就绪返回 503。飞书和索引均就绪，回执积压为 0。运行数据仍放在系统临时目录，同机备份可读。服务页的固定文案「AutoLoop 回执待补写」与实际调度器 Contractor 不符。

| 配置对象 | 可在前端完成 | 需要部署者或外部平台准备 |

| 账号与权限 | 开通审批、角色赋予、停用、撤销会话、项目读写、维护权移交、个人资料 | 主 IM 凭据、外部回调、自定义权限策略文件 |

## 建议验证顺序

1. **先让一个从前端创建的项目能发首张代码单。** 依次接通成员、来源、仓库、Agent、Worker 和额度。验证额度用尽、设备离线、凭据失效时能在发单前找到处理人并回原流程。
2. **再检查责任和配置的交接。** 分别在待验收、待资料授权、研发待接三个时点换人。验证继任人的审批范围和待办。对额度、路由及个人 Agent 设置测试并行编辑、临时中断和草稿恢复。
3. **巩固现有交付链。** 保留 PR #22 两版证据作为回归样本，验证单项附件故障和实例恢复。扩展回归运行时先确定哪些检查可做发布门禁。
