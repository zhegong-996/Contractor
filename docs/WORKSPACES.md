# 专业知识空间与授权协作

2026-11-04。页面入口为 /SUI/knowledge-workspaces。沿用 Paperclip 原版工作台，通过插件扩展功能；没有修改三个上游仓库，没有开始界面视觉改版。

## 已实现功能

| 功能 | 实现和权限真源 |
|---|---|
| 产研、增长、销售、职能空间 | 四个原生私有项目，各有专业 Agent 身份；空间成员使用原生项目授权 |
| 结构化字段、正文、来源、版本 | 原生任务文档与 Markdown 编辑器；原生页面可编辑和恢复修订；修改后旧确认失效 |
| 申请、授权与拒绝 | 绑定资料、任务、执行者、用途、期限；使用原生 request_board_approval，可在现有审批页面处理 |
| 撤权 | 原生任务级 grant；授权不打开整个专业项目；回收受限检查点和候选结论的相应身份 grant |
| 跨岗位交接 | 新岗位先获权；保留任务与检查点；结束旧执行者的任务 grant 与本任务临时资料权限 |
| 检查点与候选 | 独立私有保管项目中的原生文档，无岗位项目成员和 Agent 所有者；原任务只留引用 |
| 知识确认、撤回与采用 | 保留来源依赖；确认不自动扩大受众；人工采用后另建专业空间内的发布记录 |
| 到期和中断恢复 | 读取时检查期限；后台恢复未完成的审批、撤权和交接；同一代交接继续处理 |
| 执行中撤权 | 失去继续提交资格，清除 lease 和会话复用；原生执行请求取消，未知执行隔离到停止回执或人工核对 |
| MCP | 提供专业目录、访问申请、获准资料读取、候选沉淀和停止回执；没有 Agent 自行批准或扩大受众的工具 |

## 数据和权限

Paperclip 保存项目、成员、审批、任务、运行、grant、文档、修订与历史。SQLite 继续只保存对象映射、幂等和接入状态，没有另建业务任务库、权限引擎或 Agent 调度器。

专业资料保存在专业私有项目。跨岗位任务保存在私有协作项目。访问合同使用原生申请任务的 access-contract 文档；协作合同使用主任务的 collaboration 文档。检查点和候选在独立私有保管项目中，按身份授权。经过明确人工采用的知识另建专业空间内的发布记录，记录来源修订、采用依据、事实和受众。

合同有服务端确认凭据。直接修改 JSON 中的身份、期限、批准状态或移除检查点来源，不能扩大访问。需要恢复时使用原生修订恢复已知合同版本。

读取同时检查原生 ACL、当前任务关系、当前申请状态与期限、有效知识版本。目录按岗位和任务关系过滤，不向其他岗位任意公开全部资料标题。浏览器不接触桥接凭据；插件动作使用宿主提供的不可变身份。

## 开源复用

- Paperclip 原版：私有项目、项目成员、任务 grant、审批、checkout、取消、文档、修订、搜索、审计和插件宿主。
- Paperclip Plugin SDK 原版：构建预设、页面与侧栏注册、宿主身份、导航、Markdown 编辑与呈现。
- LLM Wiki 原版：继续作为适合共享的资料入口，受限内容没有自动复制到共享 Wiki。
- Super-agent / Autoloop 原版：前一阶段的飞书和执行接入继续使用；本阶段没有增加第二套调度器。

## 本地启用与验证

先完成 README 的基础安装与 SDK 构建，再执行：

~~~sh
npm run setup:workspaces
# 先结束现有执行，再重新加载桥接身份。
npm run stop
npm run up
npm run install:workspaces
npm test
npm run typecheck
npm run build:workspaces
~~~

首次升级早期联调状态可运行 node --import tsx scripts/migrate-workspace-contracts.ts。脚本核对原生项目和审批绑定，为旧合同生成确认凭据，不扩大原生权限。

## 真实验证

- **SUI-10 / SUI-25：原生 API 全流程。** 增长使用销售反馈与职能规范；审批前拒绝，批准后可读；检查点重试复用同一对象。产研未获权时交接被拒，重新授权后交接成功，旧执行者读不到原资料和检查点。撤权后原资料、检查点、知识候选的直接原生 API 均拒绝，旧上下文不能继续领取。负责人单独采用不含原始业务内容的流程经验到产研空间，再结束临时权限。使用明确标记的联调资料，模型调用为零。
- **SUI-19：实际浏览器全流程。** 页面完成创建、申请、授权、检查点、重新授权后交接、撤权、候选提交、版本确认、专业采用与任务完成。未授权时错误可见且输入保留。完成后再次用岗位身份核对原生 API 的拒绝。
- **异常用例。** 覆盖期限、宿主身份伪造、Agent 自批、合同篡改、失败撤权恢复、旧 lease、执行中撤权、跨任务共用 grant、中断交接同一代恢复。页面、worker、后台通过类型检查与构建。

## 当前运行边界

当前为本机管理员与四个专业 Agent 身份模式，没有冒充四位真实同事。原生私有项目支持人和 Agent；多人登录、真实员工/飞书组织映射与人员委托绑定仍需在团队部署时配置。插件拒绝未绑定的远程用户以本机管理员身份操作。

受限接口会立即拒绝失效的任务授权。原生 grant 没有 TTL，到期后的原生回收由轮询完成；服务中断时不能承诺原生 API 同时即时失效。手动撤权在原生回收完成后才记为成功，部分失败保留“撤权中”并恢复。另一有效任务仍使用共享 grant 时，只结束本任务关系，保留其他合法访问。

撤权不能从模型中收回已看过的内容。实现会回收后续资料和受限派生文档访问、隔离未知执行、阻止旧 lease，并清除自动会话复用。外部执行端的停止确认是可审计回执或人工核对，不冒充独立进程证明。

明确人工采用后的独立发布记录有自己的受众和修订；撤销原执行者临时权限不会自动删除这份独立知识。该发布能力没有向普通 Agent 开放。
