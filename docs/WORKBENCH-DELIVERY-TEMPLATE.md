# 交付模板试点

项目交付模板提供必需检查和产品验收条件。首次立项时固定到工单版次，开下一版时重新核对模板。工作台允许补充当版人工核对项。Super-agent 管理工单和委托，AutoLoop 调度 Agent，Contractor 自研模块核对证据并保存验收。原发起人在产品条件齐备后决定验收或打回原单。

~~~mermaid
flowchart LR
    A[项目与主题] --> B[工单版次和验收条件]
    B --> C[AutoLoop 派给授权 Agent 和设备]
    C --> D[本版成果及 PR 提交]
    D --> E[CI、浏览器报告与人工核对]
    E --> F{原发起人验收}
    F -->|打回| B
    F -->|通过| G[知识候选]
    G -->|采用| H[主题现行验收知识]
    H --> B
~~~

在受信任的项目仓库交付配置 `resources[].execution` 里显式启用。下面是小屏模板示例；审查账号 ID 应替换为本项目已绑定且独立于实现的人员。

```json
{
  "base": "main",
  "paths": ["collab-pilot/index.html"],
  "requiredChecks": [{ "name": "collab-pilot", "app": "github-actions", "appId": 15368 }],
  "deliveryTemplate": { "id": "store-small-screen", "version": 1, "reviewerIds": [123] }
}
```

- 模板按项目、仓库、模板 ID 和版本登记。检查、部署、审查账号或产品条件变化时提高版本。同轮接续、重新核对和交接沿用快照。原有项目可以继续使用已有交付配置。
- `product.browser` 配置固定的 GitHub Actions 工作流、必需检查、Git blob、报告名称和适用的验收项。`product.manual` 配置人工条件。完整的[门店小屏配置](../integrations/github/store-small-screen/pilot-execution.json)包含三档浏览器测量和一项人工核对。
- 工作台读取当前 PR 所属仓库、本单提交、最新 CI 和对应运行尝试。验证报告必须来自获准工作流的当次 job，提交中工作流、验证程序及依赖文件均须匹配固定 Git blob。报告中的验收项必须齐全。工作台归档结构化证据，保留报告及运行入口。开启浏览器验证时，工作台实例需能通过已配置的 GitHub 账号读取 Actions 和仓库内容，并提供 `gh` 和 `unzip`。
- 工单交付页「需求验收」逐项显示自动和人工结果。原发起人可记录人工观察、打回并在下一版调整核对项。「重新核验」从当前 GitHub PR 取证。最终验收会再查 PR、CI、独立审查及已配置的部署环境。已验收的证据绑定当时的提交和运行尝试。
- 发起人验收后生成一份候选，可审核正文和适用范围并采用。主题页展示当前已采用的验收知识。代码工单可沿用同主题、同交付模板版次的已采用规则，也可在发起时关闭自动沿用。打开项目记忆的只读工单可按主题检索规则。验收书面结论需要更新时，可用新依据完成验收，再由知识负责人替代旧条目。此前工单保留历史出处。

## 门店小屏联调

在配置好的测试仓里使用[小屏专用 CI](../integrations/github/store-small-screen/README.md)。用 280px 视口下正文宽度分别为 228px 和 244px 的两个样例，核对通过和不通过的结果。可对当前提交重跑 CI，核对同一提交的多次检查和历史版本记录。专用 CI 产物入库需要测试仓的基线包含该工作流。测试验收、GitHub 分支合并和应用发布分别记录。
